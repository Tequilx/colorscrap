# คู่มือโปรเจกต์ ColorScrap (สำหรับคนที่ไม่ได้เขียนโค้ดเอง)

เอกสารนี้ตอบคำถามเดียว: **"อยากปรับสิ่งนี้ ต้องไปแก้ที่ไหน"**
ทุกค่าที่ยกมาในเอกสารนี้ตรวจจากโค้ดจริงของ `main` ณ วันที่เขียน ถ้าโค้ดเปลี่ยนไปแล้ว ให้เชื่อโค้ดมากกว่าเอกสาร

> **คำศัพท์ที่จะเจอบ่อย**
> - **ตัวแปร / ค่าคงที่** = ชื่อที่เก็บตัวเลขหรือข้อความไว้ เช่น `INK_CAP = 0.85` แปลว่า "ค่า INK_CAP คือ 0.85"
> - **hex** = รหัสสีแบบ `#5FA3C8` (ตัวอักษร 6 ตัวหลัง `#`)
> - **component (คอมโพเนนต์)** = ชิ้นส่วนหน้าจอหนึ่งชิ้น ไฟล์นามสกุล `.vue` (เช่น ปุ่ม การ์ด หน้าสมุด)
> - **view (วิว)** = "หน้าจอ" หนึ่งหน้าของแอป เช่น หน้าเลือกอารมณ์ หน้าวาดรูป
> - **store (สโตร์)** = ที่เก็บสถานะกลางของแอป (เช่น "ตอนนี้อยู่หน้าไหน") อยู่ในโฟลเดอร์ `src/stores/`
> - **token (โทเคน)** = ค่าดีไซน์ที่ใช้ซ้ำทั้งแอป (สี เวลาแอนิเมชัน) เก็บไว้ที่เดียวเพื่อแก้ครั้งเดียวเปลี่ยนทั้งแอป
> - **fluid (ฟลูอิด)** = ระบบจำลองน้ำไหลที่ทำให้สีน้ำบนผ้าใบกระจายและผสมกัน (ใช้ WebGL คือเทคโนโลยีวาดภาพด้วยการ์ดจอบนเว็บ)
> - **ms** = มิลลิวินาที (1000 ms = 1 วินาที)
> - **Claude Code** = ผู้ช่วยเขียนโค้ดที่คุณสั่งเป็นภาษาไทยได้ ทุกหัวข้อในหมวด 3 มี "ประโยคตัวอย่าง" ให้คัดลอกไปสั่ง

## 1. ภาพรวม: แอปทำงานยังไง

ColorScrap คือสมุดสีน้ำสำหรับระบายความรู้สึก มีโต๊ะใบเดียว (หน้าจอขนาด 1280×800 ที่ย่อขยายตามหน้าต่าง) และวัตถุบนโต๊ะเลื่อนไปมา ไม่มีการเปลี่ยนหน้าเว็บจริง ๆ

1. **เปิดแอป** → ถ้ายังไม่มีโปรไฟล์ไปหน้า `hello` (ตั้งชื่อ เลือกรูปตัวแทน สีปก) ถ้ามีแล้วไปหน้า `cover` (ปกสมุด) ถ้าใช้ Supabase จริงและยังไม่ล็อกอินจะเจอ `login` ก่อน
2. กด **"เลือกความรู้สึกวันนี้"** → หน้า `pick` เลือกอารมณ์ 1 ใน 8 และความเข้ม 3 ระดับ
3. กด **"เริ่มระบาย"** → หน้า `paint` ผ้าใบน้ำไหลจะหยดสีของอารมณ์นั้นให้เอง ผู้ใช้ปาด เติมหยด หรือ (ถ้าอารมณ์ลบ) เติมสีอุ่นได้
4. กด **"บันทึกลงสมุด"** → แอปจับภาพผ้าใบ ดูดสีเด่นออกมา (สูงสุด 5 สี) แล้วเล่นแอนิเมชัน: ผ้าใบหดเป็นโพลารอยด์ → สมุดเลื่อนเข้า → ภาพลงช่อง → เทปแปะ → การ์ดสรุป (หน้า `saved`)
5. ภาพขึ้น **Supabase** (ฐานข้อมูลออนไลน์) ถ้าใช้โหมดจริง หรือเก็บในเครื่องถ้าใช้โหมด mock
6. กด **"ดูสมุดทั้งเล่ม"** → หน้า `book` เห็นภาพของแต่ละวัน และ **จานสีประจำวัน** (สีผสมของทั้งวัน + ชื่อสี เช่น "ฟ้าอมเหลืองยามเช้า") กดภาพเพื่อดูเดี่ยวและชาร์ตสีที่หน้า `photo`

**view ทั้งหมด (8 หน้า)** ชื่อที่ใช้ในโค้ดอยู่ที่ `VIEWS` ใน [src/stores/app.js](../src/stores/app.js)

| view | คือหน้าอะไร |
|---|---|
| `login` | เข้าสู่ระบบ/สมัคร (เฉพาะโหมด Supabase จริง) |
| `hello` | ทำความรู้จัก: ชื่อ รูปตัวแทน สีปก สิ่งที่ทำให้ใจฟู (ก็คือหน้าตั้งค่า) |
| `cover` | ปกสมุดปิด ทักทายตามเวลา แถบ 7 วันล่าสุด |
| `pick` | เลือกอารมณ์และความเข้ม |
| `paint` | ผ้าใบระบายสี |
| `saved` | ช็อตซูมหลังบันทึก + การ์ดสรุป |
| `book` | สมุดเปิดเต็มเล่ม + จานสีประจำวัน |
| `photo` | ดูภาพเดี่ยวขยาย + ชาร์ตสี |

การเปลี่ยนหน้าที่ **ทำได้** ถูกกำหนดไว้ในตาราง `ALLOWED` ในไฟล์เดียวกัน (เช่น `paint` ไป `saved`, `pick`, `book`, `cover` ได้)

### 1.1 การเปลี่ยนหน้า (view)

**แอปนี้ไม่ใช้ router** (ตัวจัดการหน้าเว็บแบบ Vue Router ที่ให้แต่ละหน้ามีไฟล์/ที่อยู่ของตัวเอง) แต่ใช้ตัวแปร `view` ใน store ที่ [src/stores/app.js](../src/stores/app.js) เป็นตัวบอกว่า "ตอนนี้โต๊ะอยู่หน้าไหน" วัตถุหลักบนโต๊ะ (สมุด กระดานวาด กล่องเลือกอารมณ์) **ไม่ถูกลบออกเวลาเปลี่ยนหน้า** แต่เลื่อน/ย่อ/จางตามค่า `view` ส่วนที่เหลือ (เช่น หน้าทำความรู้จัก หน้าปก การ์ดหลังบันทึก) แสดงเฉพาะตอน `view` เป็นหน้านั้น (เงื่อนไขอยู่ใน `src/App.vue`)

กฎของการเปลี่ยนหน้า:
- ทุกปุ่มเปลี่ยนหน้าผ่านฟังก์ชัน `go('ชื่อหน้า')` ใน `app.js` ซึ่งเช็กตาราง `ALLOWED` (ในไฟล์เดียวกัน) ก่อน **ถ้าหน้าปลายทางไม่อยู่ในรายการที่ไปได้ จะไม่เกิดอะไรขึ้น** (`go` คืนค่า false) ระหว่างเล่นแอนิเมชันตอนบันทึก `go()` จะถูกปฏิเสธทุกหน้า (กันกดซ้ำ)
- ส่วนที่ต้องทำทุกครั้งที่เข้าหน้าใหม่ (เช่น เปิดสมุดที่วันล่าสุด หยดสีเริ่มต้นเมื่อเข้า paint) อยู่ในฟังก์ชัน `enter()` ใน `app.js`
- **URL ผูกกับ `view`** (ไฟล์ [src/lib/useHashView.js](../src/lib/useHashView.js)): ทุกครั้งที่หน้าเปลี่ยน ส่วนท้าย URL จะเปลี่ยนเป็น `#ชื่อหน้า` เพื่อให้ปุ่มย้อนกลับ/ไปข้างหน้าของเบราว์เซอร์ใช้ได้ ปุ่มย้อนกลับ **ข้ามตาราง `ALLOWED` ได้** (ใช้ `setView()` ซึ่งยกเลิกแอนิเมชันที่ค้างอยู่ด้วย) แต่พิมพ์ `#...` เปิดตรง ๆ ได้เฉพาะ `login hello cover pick paint book photo` และต้องผ่านเงื่อนไข: ถ้ายังไม่ล็อกอิน (โหมดจริง) เข้าได้แค่ `login` · ล็อกอินแล้วเข้า `login` ไม่ได้ · ต้องมีโปรไฟล์จึงเข้าหน้าอื่นนอกจาก `hello` ได้ · `photo` ต้องมีภาพที่เปิดอยู่ · **`saved` เปิดจาก URL ตรง ๆ ไม่ได้** (URL จะโชว์ `#saved` ได้ตอนอยู่หน้านั้น แต่รีเฟรชแล้วระบบจะดึงกลับหน้าเดิม)
- ตอนเปิดแอป (`app.boot`): ยังไม่ล็อกอิน → `login` · ไม่มีโปรไฟล์ → `hello` · มีโปรไฟล์ → `cover` (ถ้า URL มี `#...` ที่ใช้ได้ จะใช้ตาม URL)

**แผนภาพลำดับหน้า** (ลูกศรคือปุ่มปกติที่ผ่าน `go()`)

```
เปิดแอป
  ├─ ยังไม่ล็อกอิน (โหมดจริง) ──→ login ──┬─ ไม่มีโปรไฟล์ ──→ hello ──→ cover
  │                                      └─ มีโปรไฟล์ ─────────────────→ cover
  ├─ ไม่มีโปรไฟล์ ──→ hello ──→ cover
  └─ มีโปรไฟล์ ─────────────────→ cover

(จาก cover กดปุ่มตั้งค่าไป hello โหมดแก้ไข แล้วกด "บันทึก" กลับ cover)

ลูกศรทุกเส้นระหว่างหน้า (ตรงกับ ALLOWED):

  login ──→ hello     login ──→ cover     hello ──→ cover
  cover ──→ pick      cover ──→ book      cover ──→ hello
  pick  ──→ paint     pick  ──→ cover
  paint ──→ saved     paint ──→ pick      paint ──→ book      paint ──→ cover
  saved ──→ book      saved ──→ pick
  book  ──→ paint     book  ──→ cover     book  ──→ photo
  photo ──→ book

เส้นทางหลักที่ผู้ใช้เดินบ่อย:
login → hello → cover → pick → paint → saved → book → photo → book
แล้ววนระบายภาพถัดไปได้สองทาง: saved → pick  หรือ  book → paint
```

**ตัวอย่างคำสั่งให้ Claude Code แก้การเปลี่ยนหน้า และต้องแก้ที่ไหน**

1. *"ปุ่ม 'หน้าแรก' ในหน้า paint ให้พาไปหน้า pick แทน cover"*
   → แก้ `go('cover')` เป็น `go('pick')` ที่ปุ่มใน `src/components/paint/DrawingBoard.vue` (`ALLOWED.paint` มี `pick` อยู่แล้ว จึงไม่ต้องแก้ตาราง)

2. *"ปุ่ม 'เปิดสมุด' ที่หน้าปกให้ไปหน้า paint เลย"*
   → แก้ที่ปุ่มใน `src/components/cover/CoverIntro.vue` และเพิ่ม `'paint'` ในรายการของ `cover` ใน `ALLOWED` (`src/stores/app.js`) เพราะตอนนี้ `cover` ไป `paint` ตรง ๆ ไม่ได้ (และให้ตรวจ `enter()` ว่าเข้า paint จากหน้าปกแล้วหยดสีเริ่มต้นถูกต้อง)

3. *"หลังบันทึกให้ไปหน้า book เลย ไม่ต้องผ่าน saved"*
   → จุดที่พาไป `saved` คือ `enter(VIEWS.saved)` สองจุดในฟังก์ชัน `runSaveSequence` ใน `src/stores/app.js` (ทางลดแอนิเมชัน และจังหวะ `sch.book[0]` ในลำดับปกติ) เปลี่ยนเป็น `enter(VIEWS.book)` (`paint → book` ได้อยู่แล้วในตาราง) **แต่ต้องรู้ก่อนว่าหน้า `saved` ไม่ใช่แค่หน้าเปล่า** มันคือที่เล่นแอนิเมชันโพลารอยด์ลงช่อง (`SavedFlight.vue`, มุมซูมของสมุดใน `Scrapbook.vue` ค่า `OPEN.saved`, `PhotoPage` โหมด `saved`) และการ์ด "แปะลงสมุดแล้ว" (`SavedCard.vue`) ซึ่งโชว์สีในภาพ/สีของวันที่เปลี่ยน ถ้าข้ามไปจะเสียส่วนเหล่านี้ ให้บอก Claude Code ให้ชัดว่าจะ "ตัดทิ้ง" หรือ "ย้ายไปแสดงในหน้า book" และให้แก้ SPEC §4.1 §5.4 กับเอกสารนี้ตามด้วย

4. *"เพิ่มหน้าใหม่ เช่น หน้า 'สถิติ' ที่ไปได้จากหน้าปก"*
   → ต้องแก้หลายที่: เพิ่มชื่อใน `VIEWS` และตาราง `ALLOWED` (`src/stores/app.js`), สร้าง component ใหม่ใน `src/components/` แล้วเพิ่มบรรทัดแสดงตาม `app.view` ใน `src/App.vue`, เพิ่มชื่อใน `HASH_VIEWS` ของ `src/lib/useHashView.js` (ถ้าอยากให้ย้อนกลับ/เปิดผ่าน URL ได้), เพิ่มปุ่มที่ `CoverIntro.vue` และอัปเดตตาราง SPEC §4.1/§4.3 (วัตถุบนโต๊ะอยู่ที่ไหนในหน้าใหม่)

5. *"ปุ่มย้อนกลับของเบราว์เซอร์ไม่ควรกลับไปหน้า hello"*
   → แก้ `accepts()` ใน `src/lib/useHashView.js` (ตัวตัดสินว่า `#...` ไหนรับได้)

> **คำแนะนำ:** ก่อนให้แก้เรื่องการเปลี่ยนหน้า ให้บอก Claude Code ให้ "ขอแผนก่อนลงมือ" เพราะการเปลี่ยนหน้าผูกกับแอนิเมชัน การล้างสถานะผ้าใบ และการล็อกกดซ้ำ

## 3. สูตรปรับแต่ง (ส่วนสำคัญที่สุด)

รูปแบบแต่ละหัวข้อ: **ไฟล์ → ตัวแปร → ค่าตอนนี้ → ตัวอย่างการแก้ → ผลที่เห็น → ประโยคสั่ง Claude Code**

กฎทั่วไป: แก้เสร็จให้เปิดหน้าเว็บที่รัน `npm run dev` ดู (หน้าเว็บอัปเดตเองเกือบทุกกรณี) และก่อนเก็บงานให้รัน `npm test` และ `npm run build` ว่าผ่าน

### 3.1 สีของแต่ละอารมณ์ (8 อารมณ์) และชื่อภาษาไทย

**สี** → ไฟล์ [src/lib/tokens.js](../src/lib/tokens.js) → ตัวแปร `EMOTION_COLORS`

| คีย์ (ห้ามเปลี่ยน) | ชื่อไทย | สี (hex) ตอนนี้ |
|---|---|---|
| `happy` | สุขใจ | `#F1BE48` |
| `calm` | สงบ | `#5FA3C8` |
| `excited` | ตื่นเต้น | `#E2688A` |
| `warm` | อบอุ่นใจ | `#CF8A4A` |
| `sad` | เศร้า | `#4256A8` |
| `angry` | โกรธ | `#D6453A` |
| `anxious` | กังวล | `#6E4FA0` |
| `tired` | เหนื่อย | `#5B6773` |

**ชื่อไทยและชื่อสีเม็ดสี (pigment)** → [src/lib/emotions.js](../src/lib/emotions.js) → ตัวแปร `META` (แต่ละอารมณ์มี `th` ชื่อไทย และ `pigment` ชื่อสีวาดภาพที่โชว์บนหน้า pick เช่น "สงบ · Cerulean Blue · พอประมาณ")

**ตัวอย่างการแก้**
```js
// tokens.js
calm: '#5FA3C8',   →   calm: '#4FB0C6',

// emotions.js (META)
calm: { th: 'สงบ', pigment: 'Cerulean Blue' },   →   calm: { th: 'สงบนิ่ง', pigment: 'Cerulean Blue' },
```

**ผลที่เห็น:** สีนี้ใช้ทั้งปุ่มอารมณ์ (pick), สีของหยดบนผ้าใบ (paint), สีหยดในแถบ 7 วัน/แท็บสมุด และสีป้ายต่าง ๆ ชื่อไทยโผล่ที่หน้า pick, การ์ดอารมณ์ในหน้า paint, ชื่อใต้หยดบนเส้นเวลา, ประโยคสรุปในจานสี

**ข้อควรระวัง**
- **คีย์ภาษาอังกฤษ (`calm`, `sad` …) ห้ามเปลี่ยนชื่อ** เพราะฐานข้อมูล Supabase (`supabase/schema.sql`) บังคับว่าต้องเป็น 8 คีย์นี้เท่านั้น
- สีบนผ้าใบ **ไม่ได้ตรงกับ hex เป๊ะ ๆ โดยอัตโนมัติ**: ความเข้มของน้ำสีแต่ละอารมณ์ปรับไว้ด้วย `brightness` ใน `FLUID_PARAMS` (หัวข้อ 3.3) ถ้าเปลี่ยน hex ไปไกลจากเดิมมาก สีบนผ้าใบอาจดูจางหรือเข้มกว่าที่คิด ต้องจูน `brightness` ตาม (CLAUDE.md แนะนำให้วัดด้วยตัวดูดสี ไม่ใช่เดา)
- สีจางและสีเข้มของแต่ละอารมณ์ (ใช้ในขอบหยด) คำนวณเองจาก hex หลัก: ใน `emotionShades` ฟังก์ชัน `deep` = ผสมไปทาง `#1a1a22` 35%, `light` = ผสมไปทางขาว 60%
- สีที่อารมณ์ลบจะ "เปลี่ยนไปทางบวก" (สีอุ่น) แยกอยู่ที่ `SHIFT_TARGETS` ดูหัวข้อ 3.4

**ประโยคสั่ง Claude Code**
> "ช่วยเปลี่ยนสีอารมณ์ 'สงบ' (calm) ใน tokens.js เป็น #4FB0C6 แล้วดูว่าสีบนผ้าใบยังตรงกับสีนี้ไหม ถ้าจางหรือเข้มไปให้จูน brightness ของ calm ใน FLUID_PARAMS โดยวัดจากตัวดูดสี ห้ามเปลี่ยนคีย์ 'calm'"

> "เปลี่ยนชื่อไทยของอารมณ์ 'warm' จาก 'อบอุ่นใจ' เป็น 'อุ่นๆ' ในทุกที่ที่แสดง"

### 3.3 Fluid: ความเร็ว การกระจาย ความหนืด ขนาดหยด ความเข้ม และสีจางเร็วแค่ไหน

ทั้งหมดอยู่ใน [src/lib/emotions.js](../src/lib/emotions.js) (บางตัวอยู่ใน `FluidCanvas.vue`) ผลทั้งหมดเห็นที่หน้า **paint**

**ก. พารามิเตอร์แยกตามอารมณ์: `FLUID_PARAMS`**

| ค่า | ความหมาย (ภาษาง่าย) |
|---|---|
| `brightness` | ความเข้มของน้ำสี (1 = เท่า hex ของอารมณ์ ยิ่งมากยิ่งเข้ม ถูกจำกัดโดย `INK_CAP`) |
| `speed` | ความเร็วที่หยดพุ่งออกจากจุดที่หยด (ยิ่งมากยิ่งกระจายไกล) |
| `curl` | ความ "ม้วน/หมุนวน" ของน้ำ (ยิ่งมากยิ่งเป็นลายวน) |
| `velDiss` | ความหนืด/แรงเสียดทาน (ยิ่งมาก น้ำหยุดไหลเร็วขึ้น ราว 1/velDiss วินาที) |
| `radius` | ขนาดของหยด (ยิ่งมากหยดยิ่งใหญ่) |
| `bleed` | สัดส่วนสีของหยดที่ "ซึม" ออกทีหลัง (0–0.9) ยิ่งมากหยดแรกยิ่งจาง แต่ซึมกว้าง |
| `reach` | ขนาดวงซึมสุดท้ายเทียบรัศมีหยดแรก (เท่า) ใช้เมื่อ `bleed` > 0 |
| `splash` | ตัวคูณจำนวนหยดตอนสาด 3 ค่า [นิดหน่อย, พอประมาณ, มากเลย] ของอารมณ์นี้ |
| `pattern` | รูปแบบการหยดเริ่มต้น (ดูตารางด้านล่าง) |

**ค่าตอนนี้**

| อารมณ์ | brightness | speed | curl | velDiss | radius | bleed | splash [นิด, พอ, มาก] | pattern |
|---|---|---|---|---|---|---|---|---|
| happy สุขใจ | 2.0 | 1.3 | 18 | 0.35 | 0.15 | 0 | 1, 1, 1 | burst |
| calm สงบ | 1.8 | 0.5 | 6 | 0.5 | 0.2 | 0 | 1.1, 1.25, 1.8 | drift |
| excited ตื่นเต้น | 2.0 | 1.4 | 30 | 0.3 | 0.12 | 0 | 0.47, 0.59, 0.35 | burst |
| warm อบอุ่นใจ | 2.0 | 1 | 12 | 0.4 | 0.22 | 0 | 1, 1, 1 | burst |
| sad เศร้า | 1.7 | 0.5 | 8 | 0.5 | 0.18 | 0 | 0.9, 1.0, 1.12 | fall |
| angry โกรธ | 2.0 | 1.3 | 26 | 0.3 | 0.13 | 0 | 1, 1, 1 | pulse |
| anxious กังวล | 1.9 | 1 | 22 | 0.35 | 0.09 | 0 | 1, 1, 1 | scatter |
| tired เหนื่อย | 1.6 | 0.2 | 4 | 0.55 | 0.2 | 0 | 1, 1, 1 | still |

**pattern แปลว่า:** `burst` กระจายรอบทิศ · `drift` ไหลช้า · `fall` ไหลลงข้างล่าง (มีแรงถ่วงเบา ๆ ช่วง 4 วินาทีแรก) · `pulse` พุ่งเป็นจังหวะ (หยดเหลื่อมกัน 260 ms) · `scatter` จุดเล็กกระจายทั่วกระดาษ · `still` แทบนิ่ง

**ข. จำนวนหยดเริ่มต้น การสาด และตัวคูณตามความเข้ม**
- `INITIAL_SPLATS` (หยดตอนเข้าหน้า paint): happy 5, calm 3, excited 3, warm 3, sad 3, angry 3, anxious 6, tired 2
- **การสาด** ตอนเข้าหน้า paint หยดไม่ลงพร้อมกัน แต่ทยอยลงภายใน `splashMs` (1000 ms) ตาม pattern ของอารมณ์ แล้วแต่ละหยดซึมต่อ
- **ระดับอารมณ์** (นิดหน่อย/พอประมาณ/มากเลย) ใช้ `SPLASH_LEVELS` ใน `emotions.js` คูณ 3 อย่าง: จำนวนหยด (`count`: 1.5 / 3.0 / 4.8), ขนาดหยด (`size`: 1.2 / 1.5 / 2.2), ระยะกระจาย (`spread`: 1.15 / 1.25 / 1.35) และตัวคูณ `splash` เฉพาะอารมณ์ ปรับสดได้ในแผง `?debug` ส่วน "สาดสีตอนเข้าหน้า (ตามระดับ)" และสไลเดอร์ "สาด×…" ของแต่ละอารมณ์
- `INTENSITY_FACTOR = [0.6, 1, 1.5]` ยังคูณ **ความเข้มสีต่อหยด** (และน้ำหนักจานสีของวันใช้สูตรของตัวเองใน `palette.js` ไม่เกี่ยวกับสองค่านี้)

**ข2. การซึมเป็นวง (bleed) — ปิดไว้ (`bleed` = 0)**
- หยดแต่ละหยด (หยดเริ่มต้นและการแตะ) ลงสีแรก (1 − `bleed`) ทันที ส่วนที่เหลือซึมออกเป็นวงกว้างขึ้นเรื่อย ๆ จนกว้าง `reach` เท่าของรัศมีหยดแรก ใช้เวลา `bleedMs` = 3500 ms (ค่ากลางใน `FLUID_GLOBAL`) แล้วหยุด เพราะการดันน้ำอย่างเดียวขยับก้อนสีไปทั้งก้อนแต่ไม่ทำให้พื้นที่สีโต
- ทดสอบแล้วว่าวงสีที่ขยายเองดูเป็น airbrush ไม่ใช่สีน้ำ จึงปิดไว้ ถ้าอยากลองเปิดเพิ่ม `bleed` ใน ?debug (เพิ่ม `reach` ให้กว้างขึ้น `bleedMs` ให้นานขึ้น)

**ค. สีจางเร็วแค่ไหน** (**ไม่ได้แยกตามอารมณ์**)
- ตัวแปร `DENSITY_DISSIPATION = 0` ใน `emotions.js` ใช้ **เท่ากันทุกอารมณ์** และต้องเป็น **0 พอดี** สีจึงไม่จางเลย (เหมือนสีน้ำแห้งติดกระดาษ) **อย่าตั้งเป็นค่าเล็ก ๆ เช่น 0.0001**: บัฟเฟอร์สีของไลบรารีเป็นเลข 16 บิต ค่าเล็ก ๆ ก็ทำให้สีหายเกือบหมดใน 1 นาที (วัดแล้ว)
- ความต่างระหว่างอารมณ์อยู่ที่ `curl`, `speed`, `radius` และ `velDiss` (น้ำหยุดนิ่งเร็ว/ช้า) ไม่ใช่การจางของสี ค่า `curl` สูงทำให้น้ำวนต่อไม่หยุด

**ง. ตัวกันสีสะสมจนดำ: `INK_CELL` และ `INK_CAP`**
- เพราะสีไม่จาง การหยดซ้ำที่เดิมจะบวกสีไปเรื่อย ๆ จนดำ จึงมีตัวกัน: แบ่งผ้าใบเป็นช่องละ **`INK_CELL = 80`** พิกเซล และจำกัดปริมาณสีรวมต่อช่องไว้ที่ **`INK_CAP = 0.85`** (หน่วยคือค่าสีสูงสุดของช่องสีหนึ่งในบัฟเฟอร์ 1 = ดำสนิท) จำกัด **ตอนหยดจริง** หยดที่ที่ว่างไม่พอจะถูกลดแรงลงให้พอดีเพดาน ช่องที่เต็มแล้วจะไม่เติมสีและดันน้ำเบาลง
- ปรับ `INK_CAP` มากขึ้น = ซ้อนสีได้เข้มขึ้น (เสี่ยงดำ) / น้อยลง = สีบางลงและซ้อนไม่ค่อยเข้ม ค่า `brightness` ของแต่ละอารมณ์ที่เกิน `INK_CAP ÷ ค่าสีสูงสุดของสีนั้น` (~1.1 แดง ถึง ~1.4 ชมพู) จะไม่มีผลเพิ่ม
- ปรับสดได้ที่ `?debug` (ค่ากลาง "เพดานสี/ช่อง") และวัดผลด้วย `scripts/measure-fluid.mjs` (ดูหัวไฟล์สคริปต์)

**จ. ค่าคงที่อื่นใน [src/components/paint/FluidCanvas.vue](../src/components/paint/FluidCanvas.vue)** (แก้ได้แต่กระทบหลายอย่าง ควรให้ Claude Code ทำ)

| ตัวแปร | ค่า | คือ |
|---|---|---|
| `SMEAR_RADIUS` | 0.25 | ขนาดรอยปาดของเครื่องมือ "ปาดสี" |
| `SMEAR_FORCE` | 1500 | แรงปาด (ยิ่งมากยิ่งลากน้ำไปไกล) |
| `DROP_RADIUS_SCALE` | 3 | ตัวคูณขยายขนาดหยดจาก `radius` (หยดเล็กเกินไปบนกระดาษใหญ่) |

### 3.6 ความเร็วแอนิเมชันทั้งหมด (MOTION tokens) และ ?motion=slow

**ค่ากลาง** → [src/lib/tokens.js](../src/lib/tokens.js) → ตัวแปร `MOTION` (หน่วย ms)

| ค่า | ตอนนี้ | ใช้กับ |
|---|---|---|
| `swap` | 450 | เปลี่ยนสถานะเล็ก ๆ (ปุ่ม แท็บ fade ฉากหลังหน้า photo) |
| `settle` | 600 | วัตถุบนโต๊ะเปลี่ยนตำแหน่ง (สมุดเลื่อน กระดานเลื่อน ภาพบินหน้า photo) |
| `fade` | 150 | เพดานเวลาเมื่อผู้ใช้เปิด "ลดการเคลื่อนไหว" |
| `ease` | `cubic-bezier(.2,.8,.2,1)` | ความรู้สึกของการเคลื่อนไหว (เร็วแล้วค่อย ๆ ชะลอ) |
| `reveal` | `lead 170, step 150, seep 600, rise 350, fade 400` | จานสีประจำวันปรากฏทีละส่วนตอนเข้าหน้า book (เริ่มหลังสมุดเข้าที่ 170 ms แล้วเรียงห่างกัน 150 ms) |
| `save` | `shrink 400, bookAt 150, drop 400, tape 200, cardLead 100, card 300` | ลำดับตอนบันทึก (รวมราว 1.55 วินาที ถ้ามีแผ่นแทรกใหม่จะ +450 ms) |

**วิธีปรับ**
```js
// ให้ลำดับบันทึกช้าลง ดูชัดขึ้น: เพิ่ม drop กับ shrink
save: { shrink: 400, ... drop: 400, ... }   →   save: { shrink: 600, ... drop: 600, ... }

// ให้การเคลื่อนของวัตถุทั้งแอปช้าลง
settle: 600,   →   settle: 800,
```
- `swap` และ `settle` ถูกผูกกับ class `duration-450` / `duration-600` ของ Tailwind ผ่าน `tailwind.config.js` และคูณด้วย `--motion-scale` ด้วย จึงเปลี่ยนทั้งแอปจากที่เดียว
- **ที่ยังกำหนดเวลาไว้ในไฟล์ของตัวเอง (ไม่ได้ใช้ `MOTION`):** แผ่นแทรกพลิก (450 / 300 / 120 / 330 ms ใน `<style>` ของ `src/components/book/PhotoPage.vue`), การ์ดหลังบันทึก (300 ms ใน `<style>` ของ `src/App.vue`), fade ของหน้าต่าง ๆ (450 ms ใน `src/App.vue`) ถ้าอยากเปลี่ยนสิ่งเหล่านี้ให้ระบุกับ Claude Code ตรง ๆ

**`?motion=slow`** (เฉพาะตอนรัน `npm run dev`): ต่อท้ายที่อยู่หน้าเว็บ เช่น `http://localhost:5173/?motion=slow` ทำให้ **ทุกแอนิเมชันช้าลง 3 เท่า** ใช้ดูทีละเฟส (ไม่ทำงานใน build จริง) ค่า 3 ตั้งไว้ที่ `TIME_SCALE` ใน [src/lib/motion.js](../src/lib/motion.js)

**ลดการเคลื่อนไหว (Reduce Motion):** ถ้าเครื่องผู้ใช้เปิด จะเหลือแค่ fade ไม่เกิน `MOTION.fade` (150 ms) ไม่มีวัตถุบิน/เลื่อน/หมุน (กฎที่ `src/assets/app.css` + `reducedMotion` ใน `motion.js`) ทดสอบได้ใน Chrome: DevTools → Rendering → Emulate CSS media "prefers-reduced-motion"

**ประโยคสั่ง Claude Code**
> "ทำให้แอนิเมชันตอนบันทึกช้าลงอีกประมาณ 50% (ปรับ MOTION.save) แล้วบอกเวลารวมใหม่"

> "ทำให้สมุดเลื่อนเร็วขึ้น เปลี่ยน MOTION.settle เป็น 450 แล้วเช็กว่าแอนิเมชันตอนบันทึกยังเข้าจังหวะกัน"

### 3.8 จานสีของวัน: สูตรผสม น้ำหนัก การตั้งชื่อ ช่วงเวลา

**ไฟล์** [src/lib/palette.js](../src/lib/palette.js) (หลักการอยู่ใน `docs/SPEC.md` §8)

**ก. น้ำหนักของแต่ละภาพ** `entryWeight = 0.75 + 0.25 × ความเข้ม` ได้ 0.75 / 1.0 / 1.25 (นิดหน่อย/พอประมาณ/มากเลย) แต่ละสีในภาพหนัก `ratio × น้ำหนักภาพ`

**ข. สูตรผสม `mixColors`** ผสมในระบบสี HSL: **hue** เป็นค่าเฉลี่ยแบบวงกลมถ่วงน้ำหนัก (นับเฉพาะสีที่ saturation เกิน `HUE_MIN_SAT = 0.15` เพื่อไม่ให้สีเทาดึง hue) ส่วน saturation กับ lightness เป็นค่าเฉลี่ยถ่วงน้ำหนัก **ทุกภาพของวันมีสิทธิ์เท่ากัน ไม่ถ่วงตามความใหม่** (จึงทำให้สีของวัน "หน่วง" เมื่อมีภาพเยอะ)

**ค. ชื่อสี `nameOfDay`** = กลุ่มสี + ตัวขยาย + ช่วงเวลา

| ส่วน | กติกา (ค่าตอนนี้) |
|---|---|
| กลุ่มสี (`hueGroup`) | hue 345–15 แดง · 15–40 ส้ม · 40–65 เหลือง · 65–170 เขียว · 170–215 ฟ้า · 215–250 น้ำเงิน · 250–290 ม่วง · 290–345 ชมพู · saturation < 0.15 = เทา |
| ตัวขยาย (`modifierOf`) ใช้ข้อแรกที่ตรง | 1) มีกลุ่มสีรอง (น้ำหนักรวมมากสุดนอกกลุ่มหลัก ไม่นับเทา) → "อม{กลุ่มรอง}" · 2) saturation 0.15–0.33 → "หม่น" · 3) saturation 0.33–0.45 หรือ lightness < 0.5 → "ครึ้ม" · 4) lightness > 0.72 → "อ่อน" · 5) saturation > 0.6 → "สด" · ไม่ตรงข้อไหน → ไม่ใส่ |
| ช่วงเวลา (`periodOf`) | 05–11 ยามเช้า · 11–14 เที่ยงวัน · 14–17 ยามบ่าย · 17–19 ยามเย็น · 19–24 ยามค่ำ · 00–05 กลางดึก |

**ช่วงเวลามาจากเวลาไหน:** จากเวลาที่บันทึกของ **ภาพล่าสุดของวันนั้น** (ตัวแปร `lastTime` ใน `dayColor`) ไม่ใช่เวลาปัจจุบัน และไม่ใช่เวลาของภาพที่ "เด่นที่สุด" (ถ้าบันทึกหลัง 19:00 ชื่อจะลงท้าย "ยามค่ำ" ตลอดไปจนสิ้นวัน)

**ง. เส้นเวลา** `TIMELINE_LEFT = 18`, `TIMELINE_WIDTH = 376` ตำแหน่งหยดตามเวลา 00:00–24:00 (`timelineX`); `spreadXs(…, minGap = 14)` ดันหยดที่ชิดกันให้ห่างอย่างน้อย 14px

**จ. สีเด่นของวัน** (สีบนแท็บสมุดและแถบ 7 วัน) `dominantColorOfDay` เลือกสีที่ `น้ำหนัก × (saturation + 0.01)` สูงสุด โดยรวมสีที่ใกล้กัน (ระยะ RGB < **40** ในฟังก์ชัน `near`) เป็นกลุ่มเดียว สีจางของน้ำซึมจึงไม่ชนะสีหยดจริง

**ฉ. ประโยคสรุปท้ายหน้าจานสี** → `summary` ใน [src/components/book/DailyPalette.vue](../src/components/book/DailyPalette.vue) (แม่แบบข้อความ ไม่ใช้ AI): ภาพ ≥ 5 → "{อารมณ์ n} · … วันนี้แวะมาบ่อยเลยนะ"; ภาพเดียว → "{อารมณ์} ตอน{ช่วง}"; อารมณ์เดียวทั้งวัน → "{อารมณ์}ทั้งวันเลย"; อื่น ๆ → "ส่วนใหญ่{อารมณ์หลัก} มีช่วง{อารมณ์รอง}ตอน{ช่วง}…" ฟังก์ชัน `dayPart` ในไฟล์เดียวกันมีเกณฑ์ช่วงเวลาของตัวเอง (เช้า 5–11, เที่ยง 11–14, บ่าย 14–17, เย็น 17–19, นอกนั้น "ค่ำ") ไม่ใช่ตัวเดียวกับ `periodOf`

**ตัวอย่างการแก้ (ให้ช่วงเย็นยาวขึ้นเป็น 17–20)**
```js
if (h >= 17 && h < 19) return 'ยามเย็น'   →   if (h >= 17 && h < 20) return 'ยามเย็น'
if (h >= 19) return 'ยามค่ำ'              →   if (h >= 20) return 'ยามค่ำ'
```
(และแก้ `dayPart` ใน DailyPalette.vue ให้ตรงกัน)

**ผลที่เห็น:** หน้า book จานสีขวา (ชื่อสี "…ยามเย็น") และการ์ดหลังบันทึก

**ข้อควรระวังสำคัญ:** ตัวอย่างใน SPEC §8.1/§8.2 เป็น **ชุดทดสอบอัตโนมัติ** ใน `src/lib/palette.test.js` ถ้าแก้สูตรแล้ว `npm test` ไม่ผ่าน อย่าไปแก้ตัวอย่างให้ผ่านเอง ให้แจ้ง Claude Code ว่าเปลี่ยน "ดีไซน์" และให้แก้ SPEC พร้อมเทสต์ด้วย

**ประโยคสั่ง Claude Code**
> "อธิบายว่าทำไมสีของวันนี้ถึงเป็น '…' แล้วลองคำนวณว่าถ้าเพิ่มภาพสีเหลืองอีกหนึ่งภาพสีของวันจะขยับแค่ไหน (ยังไม่ต้องแก้โค้ด)"

> "ผมอยากให้สีของวันไวต่อภาพล่าสุดมากขึ้น ถ่วงน้ำหนักตามความใหม่ในสูตรผสม mixColors แล้วอัปเดต SPEC §8 กับเทสต์ให้ตรงกัน ขอแผนก่อนลงมือ"

## 4. แผง `?debug` (ปรับสีน้ำสด)

**เปิดยังไง:** รันแอปด้วย `npm run dev` แล้วเปิดที่อยู่ที่มี `?debug` ต่อท้าย เช่น
`http://localhost:5173/?debug` (บน iPad ใช้ IP ของเครื่อง ดูหมวด 6) แผงจะอยู่มุมซ้ายล่าง กดหัวแผงเพื่อพับ/เปิด
**ใช้ได้เฉพาะตอน `npm run dev`** (ไม่ติดไปใน build จริง) และแผงปรับค่า **ในหน่วยความจำเท่านั้น** รีเฟรชหน้าแล้วค่าหาย จึงต้องนำค่าที่ชอบไปใส่ถาวรเอง

**ส่วนบนสุด (ตัวช่วยดูโน้ตชวน):** "นับตั้งแต่แตะครั้งแรก", "พักมือ" (วินาที) และสถานะ "โน้ต: รอ/แสดง/ปิดแล้ว"

**แถบเลือกอารมณ์:** กดเพื่อสลับอารมณ์ที่จะปรับ (สไลเดอร์ด้านล่างจะปรับของอารมณ์ที่เลือกอยู่)

**สไลเดอร์ของอารมณ์ที่เลือก** (ตรงกับ `FLUID_PARAMS`/`INITIAL_SPLATS` ใน `emotions.js`)

| สไลเดอร์ | ปรับอะไร | ช่วง |
|---|---|---|
| จำนวนหยด | `INITIAL_SPLATS[อารมณ์]` | 1–12 |
| ความเร็วหยด | `speed` | 0–3 |
| curl | `curl` | 0–60 |
| velDiss | `velDiss` | 0–2 |
| ขนาดหยด | `radius` | 0.02–0.6 |
| ความเข้ม | `brightness` | 0.5–4 |
| สัดส่วนที่ซึม | `bleed` | 0–0.9 |
| วงซึม (เท่า) | `reach` | 1–6 |

**ปุ่มของอารมณ์ที่เลือก**
- **หยดสีเริ่มต้นใหม่** ล้างผ้าใบแล้วหยดสีเริ่มต้นของอารมณ์นี้ใหม่ (ลองค่าใหม่ได้ทันที ไม่ต้องกลับไปหน้า pick)
- **คัดลอกค่า** คัดลอกค่าของอารมณ์ที่เลือกเป็นข้อความ JSON พร้อมค่ากลาง เช่น `{ "emotion": "calm", "initialSplats": 3, "brightness": 1.15, "speed": 0.3, "curl": 3, "velDiss": 1.2, "radius": 0.2, "pattern": "drift", "global": { "density": 0, "inkCap": 0.85 } }` (ถ้าเบราว์เซอร์ไม่ให้คัดลอก — เช่น เปิดผ่าน http บน iPad — จะเด้งกล่องข้อความให้คัดลอกเอง)
- **รีเซ็ตเป็นค่าเริ่มต้น** คืนค่าของอารมณ์นี้เป็นค่าที่เขียนไว้ใน `emotions.js` ตอนโหลดหน้า

**ส่วน "ค่ากลาง (ใช้ทุกอารมณ์)"** (ตรงกับ `FLUID_GLOBAL` ใน `emotions.js`)

| สไลเดอร์ | ปรับอะไร | ช่วง |
|---|---|---|
| เพดานสี/ช่อง | `inkCap` (ปริมาณสีสูงสุดต่อช่อง 80px) | 0.2–1.5 |
| จางช้า (density) | `density` (ต้องเป็น 0 พอดีถึงจะไม่จาง ค่าเล็ก ๆ ก็ทำให้สีหายใน ~1 นาที) | 0–0.01 |
| เวลาซึม (ms) | `bleedMs` | 500–8000 |
| เวลาสาด (ms) | `splashMs` | 200–3000 |

**สาดสีตอนเข้าหน้า (ตามระดับ):** สไลเดอร์ "จำนวนหยด ×" (0.3–6), "ขนาดหยด ×" (0.5–3), "ระยะกระจาย ×" (0.5–2) แยก 3 ระดับ เปลี่ยนแล้วกด "หยดสีเริ่มต้นใหม่" เพื่อดูผล

ปุ่ม **รีเซ็ตค่ากลาง** คืนค่ากลางและค่าการสาดทั้งหมด

**ส่วน "ตรวจเครื่องนี้ (อ่านจากไลบรารี)"** อ่านค่าที่ไลบรารีใช้จริงกลับมา: WebGL (WebGL2/WebGL1), รูปแบบ texture (เช่น RGBA16F), ชนิดข้อมูล (ไลบรารีใช้ half float 16 บิตเสมอ ไม่มีทางเป็น 8 บิต), linear filtering, density/velocity ที่ใช้จริง, dye/sim resolution และขนาดผ้าใบ ใช้เปิดดูบน iPad ว่าเครื่องนั้นได้ texture แบบไหน

**ส่วน "สีอุ่น (SPEC §6.4)"** (ตรงกับ `WARM_DEFAULTS` ใน `src/lib/devState.js`)

| สไลเดอร์ | ปรับอะไร | ช่วง |
|---|---|---|
| ขนาดหยด | `size` | 0.1–3 |
| ความเข้ม | `strength` | 0.5–5 |
| จำนวนลองดู | `samples` | 1–10 |
| เวลาก่อนโน้ตขึ้น (วิ) | `noteDelay` | 3–30 |
| เวลาพักมือ (วิ) | `noteIdle` | 0.5–5 |

- ปุ่ม **รีเซ็ตโน้ต** เริ่มนับเวลาโน้ตชวนของแผ่นปัจจุบันใหม่โดยไม่ล้างภาพ (โน้ตที่เคยปิดไปแล้วกลับมาถามได้อีก)
- **ทางลัด:** เปิดด้วย `?debug&shiftSpeed=10` เพื่อเร่งเวลาโน้ตทั้งสองค่า 10 เท่า (เฉพาะ dev)

**วิธีเอาค่าที่ชอบไปใส่ถาวร**
1. เลือกอารมณ์ ปรับสไลเดอร์จนพอใจ กด **คัดลอกค่า**
2. วางค่าให้ Claude Code พร้อมสั่ง เช่น:
   > "ค่านี้ปรับจากแผง debug ของอารมณ์ calm ช่วยใส่ถาวรใน emotions.js: `{ ... วางตรงนี้ ... }` (initialSplats ไปที่ INITIAL_SPLATS, ค่าอื่นไปที่ FLUID_PARAMS)"
3. หรือแก้เองใน `src/lib/emotions.js` โดยย้ายค่าตามชื่อ: `initialSplats` → `INITIAL_SPLATS`, ที่เหลือ → ในแถวของอารมณ์นั้นใน `FLUID_PARAMS`
4. **ค่าสีอุ่นและเวลาโน้ต ปุ่ม "คัดลอกค่า" ไม่ได้คัดลอกให้** (ค่ากลาง `inkCap`/`density` คัดลอกให้ใน `global`; ไปแก้ `FLUID_GLOBAL`/`INK_CAP`/`DENSITY_DISSIPATION` ใน `emotions.js`) ให้จดตัวเลขที่สไลเดอร์ แล้วแก้ `WARM_DEFAULTS` ใน `src/lib/devState.js`
5. รีเฟรช (ไม่ใส่ `?debug`) แล้วเช็กว่าค่าเป็นอย่างที่ต้องการ

**สลับยังไง:** ตัวแปร `VITE_USE_MOCK` (อ่านใน `src/lib/supabase.js` เป็นตัวแปร `USE_MOCK`): ถ้าเป็น `false` เท่านั้นถึงใช้ Supabase จริง ค่าอื่น (รวมถึงไม่ตั้ง) = mock

วิธีสลับชั่วคราวแบบไม่แตะไฟล์: ใส่หน้าคำสั่ง เช่น
```
VITE_USE_MOCK=true npm run dev      # บังคับ mock
VITE_USE_MOCK=false npm run dev     # บังคับจริง (ต้องมีค่า Supabase ใน .env.local)
```
(ตัวแปรที่ใส่ในคำสั่งชนะค่าในไฟล์ .env ทั้งหมด) **เปลี่ยนค่าในไฟล์ `.env*` แล้วต้องหยุดและรัน `npm run dev` ใหม่** จึงจะมีผล

**แต่ละไฟล์ .env ทำอะไร** (ลำดับความสำคัญ: **`.env.local` ชนะ** ไฟล์อื่น)

| ไฟล์ | อยู่ใน git ไหม | มีไว้ทำอะไร |
|---|---|---|
| `.env` | ใช่ | ค่าตั้งต้นของทุกการรัน (ตอนนี้ตั้ง mock) หมายเหตุ: ข้อความคอมเมนต์ในไฟล์นี้เก่า ไม่ตรงกับพฤติกรรมจริงแล้ว (ดู `src/lib/supabase.js`) |
| `.env.production` | ใช่ | ค่าเฉพาะตอน `npm run build` (ตัวสำเร็จรูปสำหรับใช้งานจริง ตอนนี้ตั้งเป็นโหมดจริง) |
| `.env.example` | ใช่ | แม่แบบ ใส่ชื่อตัวแปรที่ต้องมี (`VITE_USE_MOCK`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) โดยค่าเว้นว่าง |
| `.env.local` | **ไม่** (ถูกป้องกันด้วย `*.local` ใน `.gitignore`) | ไฟล์ส่วนตัวของเครื่อง เก็บการตั้งค่าที่เป็นความลับของคุณ เอกสารนี้ไม่ได้เปิดอ่านและไม่ระบุค่า อย่าส่งไฟล์นี้ให้ใคร อย่าวางในแชต |

**ถ้าอยากเริ่มใช้ Supabase จริงกับโปรเจกต์ใหม่:** (1) สร้างโปรเจกต์ที่ supabase.com (2) เปิด SQL Editor วางเนื้อหา `supabase/schema.sql` ทั้งไฟล์แล้ว Run (3) ใน Authentication ปิด "Confirm email" (4) คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ URL กับ **publishable key** ของโปรเจกต์ (ห้ามใส่ secret / service_role key ในแอป) (5) รัน `npm run dev` ใหม่

## 6. คำสั่งที่ใช้บ่อย

รันใน Terminal ที่โฟลเดอร์โปรเจกต์ (ต้องมี Node.js เวอร์ชัน 22.18+ หรือ 24.12+)

| ต้องการ | คำสั่ง | หมายเหตุ |
|---|---|---|
| ติดตั้งไลบรารี (ครั้งแรก/หลังดึงโค้ดใหม่) | `npm install` | |
| รันตอนพัฒนา | `npm run dev` | เปิดที่ `http://localhost:5173/` (ดูพอร์ตจริงในบรรทัด "Local" ของ Terminal) หน้าเว็บอัปเดตเองเมื่อแก้ไฟล์ |
| รันโหมด mock ชัวร์ ๆ | `VITE_USE_MOCK=true npm run dev` | ไม่ต้องสนใจ `.env.local` |
| รันให้ iPad/มือถือเปิดได้ | `VITE_USE_MOCK=true npm run dev -- --host` | ดูหัวข้อ "เปิดบน iPad" ด้านล่าง |
| รันชุดทดสอบ | `npm test` | ผ่านทั้งหมดก่อนเก็บงานทุกครั้ง |
| สร้างไฟล์สำหรับใช้งานจริง | `npm run build` | ผลลัพธ์อยู่ในโฟลเดอร์ `dist/` |
| ดู build ที่สร้างแล้ว | `npm run preview` | |

**เปิดบน iPad**
1. iPad กับคอมพิวเตอร์ต้องอยู่ **Wi-Fi เดียวกัน**
2. รัน `VITE_USE_MOCK=true npm run dev -- --host`
3. ดู Terminal บรรทัด **Network** จะเป็น `http://<เลข IP>:5173/` (หาเลข IP เองบน Mac ได้ด้วย `ipconfig getifaddr en0`)
4. พิมพ์ที่อยู่นั้นใน Safari บน iPad
5. ข้อจำกัด: เปิดผ่าน `http://` ทาง IP ไม่ใช่ "secure context" บางความสามารถของเบราว์เซอร์จะไม่ทำงาน (เช่นปุ่ม "คัดลอกค่า" ในแผง debug จะเด้งกล่องให้คัดลอกเอง) การบันทึกภาพใช้ได้ปกติ

**ย้อนกลับไปจุดสำรอง (backup)**
มีป้ายกำกับ (tag) ของ git ไว้ 2 อัน:
- `backup/main-before-animations` = สถานะของ `main` **ก่อนมีแอนิเมชันขั้น 9** (อยู่ทั้งในเครื่องและบน GitHub)
- `backup/animations-before-rebase` = branch แอนิเมชันก่อนจัดเรียงประวัติ (อยู่ในเครื่องเท่านั้น)

ดูรายการ: `git tag -l 'backup/*'`

วิธีที่ **ปลอดภัย** (ไม่ลบอะไร): สร้าง branch ใหม่จากจุดสำรอง แล้วใช้ branch นั้น
```
git switch -c restore-before-animations backup/main-before-animations
```
กลับมาที่งานปัจจุบันด้วย `git switch main`

วิธีที่ **ย้อน `main` กลับจริง** (ทำลายงานหลังจุดนั้นบนเครื่อง ใช้เมื่อแน่ใจเท่านั้น และถ้า push ไปแล้วจะต้องขอให้คนที่เข้าใจ git ช่วย): `git switch main` แล้ว `git reset --hard backup/main-before-animations` ให้สั่ง Claude Code ทำและให้ยืนยันก่อนเสมอ

> **ประโยคสั่ง Claude Code:** "ผมอยากดูแอปตอนก่อนมีแอนิเมชัน ช่วยสร้าง branch ใหม่จาก tag backup/main-before-animations ให้ ห้ามแตะ main"
