## 1. ภาพรวม

ColorScrap เป็นเว็บแอปสมุดสเก็ตช์ ใช้เปลี่ยนความรู้สึกที่อธิบายเป็นคำพูดได้ยากให้กลายเป็นภาพสีน้ำ ผู้ใช้ระบายความรู้สึกได้โดยไม่ต้องพิมพ์หรือเล่าให้ใครฟัง แล้วเก็บไว้เป็นบันทึกอารมณ์ประจำวัน

**กลุ่มเป้าหมาย**
- กลุ่มหลักคือนักศึกษาและคนวัยเริ่มทำงานที่มีความเครียดสะสม
- กลุ่มรองคือคนที่มักเป็นผู้รับฟังคนอื่น จนลืมดูแลความรู้สึกของตัวเอง
- คนกลุ่มนี้ไม่ชอบพิมพ์หรือเล่าความรู้สึก แอปจึงต้องใช้คำให้น้อยที่สุด และให้ความรู้สึกปลอดภัย

**ขอบเขตเวอร์ชันนี้ (ต่างจากพิตช์เดิม)**

| ในพิตช์เดิม | เวอร์ชันนี้ |
|---|---|
| เปิดกล้องให้ AI อ่านอารมณ์ | ผู้ใช้กดปุ่มเลือกอารมณ์เอง ไม่มีกล้องเลย |
| สรุปรายเดือนแบบปฏิทินหยดสี | สรุปรายวันเท่านั้น (จานสีประจำวัน) |
| ตกแต่งสมุดด้วยกราฟิกได้อิสระ | ยังไม่ทำ เก็บไว้ทำทีหลัง (ดู §12) |

AI ใช้ช่วยพัฒนาเท่านั้น ไม่มี AI อยู่ในตัวระบบ

**อุปกรณ์:** PC, Mac และ iPad แนวนอน รองรับทั้งเมาส์และนิ้ว

## 3. Design tokens

### 3.4 รูปทรงและเส้น
- **ปุ่มทรงลายมือ:** มุมโค้งไม่เท่ากัน เช่น `border-radius: 18px 22px 16px 24px` ขอบ 2px สี `--ink`
- **ปุ่มหลัก:** พื้น `--ink` ตัวหนังสือ `--paper` ความสูง 56–58px
- **ปุ่มรอง:** พื้นโปร่ง ขอบ `--ink`
- **ชิป:** ทรงแคปซูล `border-radius: 999px` สูง 44–48px
- **เงา:** ใช้กับของที่วางซ้อนบนโต๊ะเท่านั้น ได้แก่ สมุด ภาพ และการ์ด ห้ามใส่เงาให้ทุกกล่อง

### 3.5 SVG filters

สร้าง component `<SvgDefs>` วางครั้งเดียวที่ root แล้วอ้างผ่าน `filter: url(#id)`

| id | ค่า | ใช้กับ |
|---|---|---|
| `wob` | feTurbulence fractalNoise baseFrequency 0.035, numOctaves 2, seed 2 → feDisplacementMap scale 3 | ขอบปุ่ม ไอคอน หน้าบนปุ่มอารมณ์ |
| `wc` | baseFrequency 0.014, octaves 3, displacement 30, blur 1.4 | หยดสีน้ำขนาดใหญ่ (ภาพนิ่ง) |
| `wcm` | baseFrequency 0.03, displacement 18, blur 1 | ภาพย่อในสมุด หลุมผสมสี |
| `wct` | baseFrequency 0.09, displacement 7, blur 0.5 (filter region สูง: `y=-150% height=400%`) | หยดสีบนเส้นเวลา รอยพู่กัน (stroke หนา 20px) |
| `grain` | fractalNoise 0.85, alpha 0.12 | ผิวกระดาษทับทั้งโต๊ะ |

**ข้อระวังเรื่อง performance บน iPad Safari**
- ห้ามใส่ filter `wob` กับพื้นที่ใหญ่ หรือของที่ขยับตลอด
- ห้ามใส่ filter `wob` กับ element ที่มีตัวหนังสือยาว ให้ใส่ที่ pseudo-element ที่เป็นกรอบแทน
- `grain` ให้ render เป็นภาพครั้งเดียวแล้วใช้เป็น background ที่วางซ้ำ

### 3.6 Motion
- เวลาเปลี่ยนสถานะของวัตถุบนโต๊ะ: 450–600ms, `cubic-bezier(.2,.8,.2,1)`
- Hover บนปุ่มอารมณ์: หมุน -6° และขยายเป็น 1.05 เท่า
- ถ้าผู้ใช้เปิด `prefers-reduced-motion` ให้ตัดการเลื่อนและหมุนทั้งหมด เหลือแค่ fade ไม่เกิน 150ms

## 4. สถาปัตยกรรม: โต๊ะเดียว

### 4.1 สถานะของแอป

```js
// src/stores/app.js
export const VIEWS = Object.freeze({
  login: 'login', // เข้าสู่ระบบ (§7.1) ไม่ใช้ในโหมดจำลอง
  hello: 'hello', cover: 'cover', pick: 'pick',
  paint: 'paint', saved: 'saved', book: 'book',
  photo: 'photo', // ดูภาพเดี่ยว (§5.8)
})
```

`useAppStore` เก็บค่าต่อไปนี้:
- `view`: สถานะปัจจุบันของโต๊ะ
- `selection`: `{ emotion, intensity }` โดย `intensity` เป็น 0, 1 หรือ 2
- `openDate`: วันที่ที่กำลังเปิดดูในสมุด
- `leafIndex`: แผ่นที่กำลังเปิดอยู่ในวันนั้น
- `lastSavedEntryId`: id ของภาพที่เพิ่งบันทึก

**การเปลี่ยนสถานะ**

| จาก | การกระทำ | ไป |
|---|---|---|
| (โหลดแอป) | ยังไม่ได้เข้าสู่ระบบ (โหมดจริง) | `login` |
| `login` | เข้าสู่ระบบ/สมัครสำเร็จ แต่ยังไม่มีแถวใน `profiles` | `hello` |
| `login` | เข้าสู่ระบบสำเร็จ และมีโปรไฟล์แล้ว | `cover` |
| `hello` (โหมดแก้ไข) | กด "ออกจากระบบ" หรือ session หมดอายุ | `login` |
| (โหลดแอป) | ยังไม่มีแถวใน `profiles` | `hello` |
| (โหลดแอป) | มีโปรไฟล์แล้ว | `cover` |
| `hello` | กด "เริ่มใช้สมุด" | `cover` |
| `cover` | กด "เลือกความรู้สึกวันนี้" | `pick` |
| `cover` | กด "เปิดสมุด" | `book` |
| `cover` | กดปุ่มตั้งค่า | `hello` (โหมดแก้ไข) |
| `pick` | กด "เริ่มระบาย" | `paint` |
| `pick` | กด "หน้าแรก" | `cover` |
| `paint` | กด "บันทึกลงสมุด" | `saved` |
| `paint` | กด "เปลี่ยนสี" | `pick` (ภาพบนผ้าใบยังอยู่) |
| `paint` | กด "สมุด" | `book` |
| `saved` | กด "ดูสมุดทั้งเล่ม" | `book` |
| `saved` | กด "ระบายต่ออีกแผ่น" | `pick` |
| `book` | กดแถบกระดานด้านซ้าย | `paint` |
| `book` | กด "หน้าแรก" | `cover` |
| `book` | กดภาพในสมุด | `photo` |
| `photo` | กด "ปิด", กด Esc หรือคลิกพื้นที่ว่าง | `book` (วันและแผ่นเดิม) |

ถ้าอยากให้ปุ่ม back ของเบราว์เซอร์ใช้ได้ ให้ sync `view` กับ `location.hash` เช่น `#book` และ `#photo` ไม่ต้องใช้ Vue Router (`#photo` เปิดตรง ๆ จาก URL ไม่ได้ ต้องมีภาพที่เปิดอยู่ใน store ก่อน ไม่งั้นข้ามไปหน้าตามปกติ; กด back จาก `#photo` กลับ `#book` ที่แผ่นเดิม)

### 4.2 Stage scaling
- ออกแบบทุกหน้าบน stage ขนาดคงที่ **1280×800** (สัดส่วน 16:10)
- ย่อหรือขยายทั้ง stage ด้วย `transform: scale(min(vw/1280, vh/800))` แล้ววางกึ่งกลาง
- พื้นที่ที่เหลือรอบ stage ใช้สีและผิว `--desk` จะได้ดูเป็นโต๊ะต่อเนื่องกัน
- ผ้าใบ WebGL ต้องคำนวณขนาด pixel จริงจาก `getBoundingClientRect() × devicePixelRatio` (จำกัดไม่เกิน 2) ไม่ใช่ขนาดก่อน scale
- จุดสัมผัสของ pointer บนผ้าใบต้องแปลงพิกัดกลับตามค่า scale ด้วย

### 4.3 วัตถุบนโต๊ะ (component ที่อยู่ตลอด)

วัตถุเหล่านี้ไม่ถูก unmount เวลาเปลี่ยน view แต่เปลี่ยนตำแหน่ง ขนาด และความโปร่งใสด้วย class ตาม `view`

| วัตถุ | hello | cover | pick | paint | saved | book |
|---|---|---|---|---|---|---|
| `Scrapbook` | ปกตัวอย่าง (ขวา) | ปกปิด (ซ้าย-กลาง) | ซ่อนนอกจอ | ซ่อน | เปิด ซูมหน้าซ้าย | เปิดเต็มเล่ม |
| `DrawingBoard` | ซ่อน | ซ่อน | ซ่อน | เต็มจอ | ซ่อน | เหลือแถบซ้าย 92px |
| `EmotionPalette` | ซ่อน | ซ่อน | กลางจอ | ซ่อน | ซ่อน | ซ่อน |

ใน view `photo` (§5.8) วัตถุทั้งหมดอยู่ที่เดิมแบบ `book` แต่ถูกชั้นสี `--desk` ทึบ 85% ของหน้า photo ทับอยู่ และกดไม่ได้

ควร mount `DrawingBoard` ไว้ตลอดเพื่อไม่ให้ WebGL context หาย แต่หยุด loop ของ simulation ตอนที่ไม่ได้อยู่ในหน้า `paint`

### 5.0 `hello`: ทำความรู้จัก (`0-hello`)

แสดงครั้งแรกที่เข้าแอป และเปิดอีกครั้งได้จากปุ่มตั้งค่าในหน้าแรก

**ฝั่งซ้าย: กระดาษหน้าแรกของสมุด** เอียง -0.6° มีเทปแปะด้านบน
- **หัวกระดาษ:** "หน้าแรกของสมุด · แก้ทีหลังได้เสมอ" และหัวข้อ "สมุดเล่มนี้เป็นของ..."
- **ชื่อที่อยากให้เรียก:**
  - input ไม่มีกรอบ มีแต่เส้นประด้านล่าง ฟอนต์ Mali 26px
  - ยาวได้ 1–20 ตัวอักษร
  - placeholder: "เช่น ฝน, มิ้นท์, เจ้าหญิงนอนดึก"
- **ตัวแทนของฉัน:**
  - ภาพวาดเส้น 8 แบบ: `cat`, `plant`, `cloud`, `moon`, `flower`, `fish`, `mug`, `star` (path อยู่ใน §11)
  - ปุ่มสูง 60px
  - ปุ่มที่เลือกอยู่: ขอบ `--ink`, พื้น `rgba(241,190,72,.28)`, ยกขึ้น 3px และหมุน -3°
- **สีปกสมุด:** ปุ่มวงกลม 4 สี เส้นผ่านศูนย์กลาง 52px สีที่เลือกอยู่มีวงแหวน `--ink` หนา 3px
- **สิ่งที่ทำให้ใจฟู:**
  - ชิปเลือกได้หลายอัน: เพลง, แมว, กาแฟ, การนอน, เดินเล่น, วาดรูป, เกม, ทะเล วางให้ครบ 8 อันในแถวเดียว (padding แนวนอนของชิปในกลุ่มนี้ 12px)
  - ไม่บังคับเลือก
  - ชิปที่เลือกอยู่: พื้น `--ink` ตัวหนังสือ `--paper`

**ฝั่งขวา: ปกตัวอย่าง** อัปเดตทันทีที่ผู้ใช้เปลี่ยนค่า
- **ป้ายชื่อ:** "ของ {ชื่อ}" ถ้ายังว่างให้แสดง "ชื่อของคุณ" เป็นสีจาง
- **สติกเกอร์วงกลม:** มีภาพตัวแทนที่เลือก แปะที่มุมซ้ายบนของปก
- **ป้ายเทป:** แสดงสิ่งที่ทำให้ใจฟูไม่เกิน 3 อัน แปะที่ขอบขวาของปก

**ปุ่ม "เริ่มใช้สมุด":**
- ปิดใช้งาน (`disabled`) จนกว่าจะมีชื่ออย่างน้อย 1 ตัวอักษรหลังตัดช่องว่าง เพราะตาราง `profiles` บังคับชื่อ 1–20 ตัวอักษร (§7.2) และมีข้อความช่วยบอกว่า "ใส่ชื่อก่อนนะ" ใต้ปุ่ม
- ในโหมดแก้ไข (เปิดจากปุ่มตั้งค่า) ปุ่มเปลี่ยนเป็น "บันทึก" และใช้เงื่อนไขเดียวกัน

เมื่อกดปุ่ม:
1. `upsert` ข้อมูลลงตาราง `profiles`
2. เปลี่ยน view เป็น `cover`
3. ปกตัวอย่างเลื่อนไปอยู่ตำแหน่งของปกในหน้า cover

### 5.1 `cover`: หน้าแรก (`1-cover`)

**ฝั่งซ้าย: สมุดปิด** ขนาด 420×540 เอียง -2.5°
- **ปกและป้าย:** ปกใช้สีที่ผู้ใช้เลือก มีรอยสีน้ำเลอะ 3 จุดแบบเล็กและจาง (ขนาดประมาณครึ่งหนึ่งของหยดใหญ่ opacity ≈ 0.45) วางรอบขอบปก ไม่ทับป้ายกระดาษและสติกเกอร์ ป้ายกระดาษมีคำว่า "ColorScrap" และ "ของ {ชื่อ}"
- **รายละเอียดปก:** สันซ้ายมีเส้นประเย็บ และมีสายรัดแนวตั้งทางขวา
- **แท็บคั่นหน้า:** โผล่จากขอบบนของปก 3 อัน แต่ละอันใช้สีเด่นของ 3 วันล่าสุดที่มีบันทึก (สีที่ดูดได้จากภาพ ดู §7.3) วันล่าสุดสูงกว่าอันอื่น

**ฝั่งขวา: ข้อความและปุ่ม**
- **วันที่:** วันและวันที่ภาษาไทย เช่น "พฤหัสบดี 1 ตุลาคม"
- **คำทักทายตามเวลา:**
  - 05–11 น.: "สวัสดีตอนเช้า"
  - 11–16 น.: "สวัสดีตอนบ่าย"
  - 16–19 น.: "สวัสดีตอนเย็น"
  - นอกนั้น: "ดึกแล้วนะ"
- **ข้อความรอง:** "วันนี้รู้สึกยังไงบ้าง ไม่ต้องอธิบายเป็นคำพูด แค่เลือกสีแล้วปล่อยให้มันไหลไป"
- **ปุ่ม:** ปุ่มหลัก "เลือกความรู้สึกวันนี้" และปุ่มรอง "เปิดสมุด" (มีไอคอนสมุด)
- **แถบ 7 วันล่าสุด:**
  - หยดสีน้ำ 42px ต่อวัน ใช้สีเด่นของวันนั้น (§7.3)
  - วันที่ไม่มีบันทึกให้แสดงเป็นวงเส้นประ
  - วันนี้ใช้ป้าย "วันนี้" ตัวหนา
- **มุมขวาบน:** ปุ่มตั้งค่า (ไอคอนแถบเลื่อน) เปิดหน้า `hello` ในโหมดแก้ไข

### 5.2 `pick`: เลือกความรู้สึก (`2-pick`)

- **หัวข้อ:** "ตอนนี้รู้สึกแบบไหน?" และข้อความรอง "เลือกสีที่ใกล้ที่สุดหนึ่งสี ไม่มีคำตอบผิด"
- **กล่องสีน้ำ:** ขนาด 880×364 ขอบใช้ filter `wob` ภายในเป็น grid 4×2 ช่องละหนึ่งอารมณ์
- **แต่ละช่อง:** ปุ่มสูง 150px ข้างในมีหยดสีพร้อมใบหน้าขนาด 88px (`EmotionBlob`) และชื่ออารมณ์
- **ช่องที่เลือกอยู่:**
  - พื้นเป็นสีอารมณ์ที่ alpha `0x2E`
  - ขอบ `--ink`
  - ยกขึ้น 5px และหมุน -1°
  - เงาด้านล่างเป็นสีอารมณ์ที่ alpha 50%
  - ชื่ออารมณ์มีขีดเส้นใต้แบบหยัก
- **ความเข้ม:** ชิป 3 อัน "นิดหน่อย", "พอประมาณ" (ค่าเริ่มต้น) และ "มากเลย" แต่ละอันมีหยดสีขนาด 14, 21 และ 28px
- **แถวล่าง:**
  - สรุปที่เลือก เช่น "**สงบ** · Cerulean Blue · พอประมาณ"
  - ปุ่มหลัก "เริ่มระบาย →"
- **ค่าเริ่มต้น:** ใช้อารมณ์ที่เลือกครั้งล่าสุด ถ้ายังไม่เคยเลือกให้เป็น `calm`
- **การใช้คีย์บอร์ด:** ปุ่มช่องอารมณ์ใช้ `aria-pressed` และกด Tab เลื่อนได้ตามลำดับ
- **ผ้าใบมีภาพที่ยังไม่บันทึก** (นับหยดเริ่มต้นด้วย) **และมาจาก `cover` หรือ `book`:** กด "เริ่มระบาย" แล้วแทนแถวล่างด้วยข้อความ "บนผ้าใบยังมีภาพที่ยังไม่ได้บันทึก" กับ 2 ตัวเลือก (และลิงก์ "ยกเลิก" กลับมาเลือกอารมณ์ต่อ)
  - **"ระบายต่อแผ่นเดิม":** เปลี่ยน palette เป็นอารมณ์ที่เลือก แล้วหยดสีเริ่มต้นของอารมณ์นั้นทับลงบนภาพเดิม (ถ้าเลือกอารมณ์เดิมไม่ต้องหยดซ้ำ)
  - **"เริ่มแผ่นใหม่":** ล้างผ้าใบ แล้วหยดสีเริ่มต้นของอารมณ์ที่เลือก
- **มาจากลิงก์ "เปลี่ยนสี" ในหน้า `paint`:** ไม่ถามอะไร ระบายต่อบนแผ่นเดิมเสมอ (เหมือน "ระบายต่อแผ่นเดิม")
- **ผ้าใบว่างหรือเพิ่งบันทึก:** ไม่ต้องถาม กด "เริ่มระบาย" แล้วหยดสีของอารมณ์ที่เลือกทันที

### 5.3 `paint`: ผ้าใบระบายสี (`3-paint`)

- **กระดานและกระดาษ:**
  - กระดาน `--board` ขนาด 1224×744 มุมโค้ง 12px
  - กระดาษ `--paper` ขนาด 1112×612 ที่ตำแหน่ง (84, 92)
  - เทปกาวติด 4 มุม เอียงประมาณ 38°
  - `FluidCanvas` ครอบเต็มพื้นที่กระดาษ
- **ปุ่มด้านบน:**
  - ซ้ายบน: "หน้าแรก"
  - ขวาบน: "สมุด · วันนี้ {n} ภาพ"
- **การ์ดอารมณ์** (แทนพื้นที่ภาพจากกล้องในพิตช์เดิม)
  - ขนาด 228px ที่ตำแหน่ง (1000, 124) ซ้อนทับขอบขวาของกระดาษ เอียง 1.5°
  - ข้างในมีหยดสีพร้อมใบหน้าของอารมณ์ที่เลือก ชื่ออารมณ์และความเข้ม
  - มีคำแนะนำ 2 บรรทัด: "ลากนิ้วเพื่อปาดและกวนสี" และ "แตะค้างเพื่อเติมหยดสี"
  - มีลิงก์ "เปลี่ยนสี"
- **ถาดเครื่องมือ:**
  - ขนาด 740×80 ที่ตำแหน่ง (270, 690) ทับขอบล่างของกระดาษ กว้างพอสำหรับ 4 เครื่องมือ (ปุ่มละ 96×60)
  - เครื่องมือ: ปาดสี (เลือกอยู่ตอนเริ่ม), เติมหยด, **สีอุ่น**, เริ่มใหม่ (ต้นแบบ `3b-warm-tool.dc.html`)
  - **สีอุ่น** แสดงเฉพาะเมื่ออารมณ์ล่าสุดของแผ่นเป็น `sad`, `angry`, `anxious` หรือ `tired` (§6.4) ไอคอนเป็นหยดน้ำไล่สีเหลือง→พีชจาก `SHIFT_TARGETS` ปุ่มที่เลือกอยู่พื้น `--warm-tint` ถ้าอารมณ์ล่าสุดกลายเป็นบวกขณะเลือกอยู่ ให้กลับไปปาดสี
  - ตามด้วยเส้นคั่น และปุ่มหลัก "บันทึกลงสมุด"
- **ปุ่ม "เริ่มใหม่":** ไม่ใช่โหมด ต้องกดสองครั้งเพื่อยืนยัน กดครั้งแรกปุ่มเปลี่ยนเป็น "แตะอีกครั้งเพื่อล้าง" (ไอคอนเปลี่ยนด้วย) ค้างไว้ 3 วินาที ถ้ากดซ้ำในเวลานั้นจึงล้างผ้าใบแล้วหยดสีเริ่มต้นใหม่ตามอารมณ์ที่เลือกอยู่ ไม่เช่นนั้นปุ่มกลับเป็นปกติ (ไม่มี undo และไม่มี toast)
- **การหยดสีเริ่มต้นเมื่อเข้า `paint`:** หยดทุกครั้งที่ผ้าใบว่างหรือเพิ่งบันทึก (รวมถึงกลับจาก `book` ผ่านแถบ "กลับไประบาย" ตอนผ้าใบว่าง) ถ้าผ้าใบมีภาพอยู่แล้วจะไม่หยดเพิ่มเอง ยกเว้นตามกติกาใน §5.2
- **แผ่นที่มีหลายอารมณ์:** ระบบจดอารมณ์ที่หยดลงแผ่นนี้ตามลำดับ (ไม่จดซ้ำเมื่ออารมณ์ล่าสุดเท่าเดิม) ตอนบันทึกเก็บเป็น `emotions` และ `emotion` คืออารมณ์ล่าสุด ปุ่ม "เริ่มใหม่" และ "เริ่มแผ่นใหม่" ล้างรายการนี้ คำบรรยายใต้ภาพ (§5.5, §5.8) แสดง "อารมณ์แรก → อารมณ์ล่าสุด" ถ้าสองอย่างนี้ต่างกัน ไม่งั้นแสดงอารมณ์เดียว
- **โน้ตชวนลองสีอุ่น (ครั้งเดียวต่อแผ่น):** ดูเงื่อนไขใน §6.4 หน้าตาเป็นกระดาษโน้ต `--note` ติดเทป ขนาด 236px เอียง −1.8° ที่ตำแหน่ง (990, 456) ใต้การ์ดอารมณ์ (ต้นแบบวางที่ y 392 เพราะการ์ดในต้นแบบไม่มีคำแนะนำ 2 บรรทัด ในแอปจริงการ์ดสูงกว่า จึงเลื่อนลงไม่ให้ทับลิงก์ "เปลี่ยนสี") ข้อความ "อยากลองเติมสีอุ่นลงไปไหม" พร้อมไอคอนหยดสีอุ่น และปุ่ม "ลองดู" (ปุ่มหลักสีหมึก) กับ "ไว้ก่อน" (ลิงก์ขีดเส้นใต้) ทั้งสองสูง ≥ 44px
  - `role="status"` `aria-live="polite"` ปุ่มเป็น `<button>` จริง กด Tab ถึง และไม่ดึง focus มาเอง
  - "ลองดู": เลือกเครื่องมือสีอุ่น และหยดตัวอย่าง 4 หยดเรียงตามขอบกระดาษ (ไล่สีตาม `SHIFT_TARGETS`) แล้วปิดโน้ต
  - "ไว้ก่อน": ปิดและไม่ถามอีกในแผ่นนั้น (เลือกเครื่องมือสีอุ่นเองจากถาดก็ปิดโน้ตเช่นกัน)
  - "เริ่มใหม่", "เริ่มแผ่นใหม่" และการบันทึก ถือเป็นแผ่นใหม่ ถามได้อีกครั้ง
  - ห้ามมีข้อความที่ตัดสินอารมณ์ เช่น "ทำให้รู้สึกดีขึ้น"
- **รายละเอียด fluid:** ดู §6

### 5.4 `saved`: บันทึกลงสมุด (`4-saved`)

หน้านี้คือ "ช็อตซูมเข้า" ของสมุด ใช้ component สมุดตัวเดียวกับหน้า `book` แค่คนละ transform

**ลำดับแอนิเมชันหลังกดบันทึก (รวมประมาณ 1.6 วินาที)**
1. ผ้าใบหดลงเป็นภาพโพลารอยด์ แล้วเลื่อนออกไปทางซ้ายพร้อมกระดาน
2. สมุดเลื่อนเข้ามาแล้วเปิดออก โดยซูมอยู่ที่หน้าซ้ายของวันนี้
3. ภาพใหม่ลอยลงช่องเส้นประ (ใหญ่ขึ้น 1.08 เท่า เงาลึก) จากนั้นเทปแปะลงและเงาลดลง
4. การ์ดด้านขวาโผล่ขึ้นมา

**การ์ดด้านขวา** ขนาด 400px ที่ตำแหน่ง (790, 110)
- **หัวการ์ด:** ไอคอนเช็กในวงกลมสีอารมณ์ ข้อความ "แปะลงสมุดแล้ว" และบรรทัด "{เวลา} · {อารมณ์} · {ความเข้ม}"
- **"สีในภาพนี้":** หัวข้อก่อนหัวข้อ "สีของวันนี้เปลี่ยนไปนิดหนึ่ง" แสดงหยดสีน้ำเล็ก (`WatercolorBlob`) ของสีที่ดูดได้ไม่เกิน 5 หยด ขนาด 28–60px ตาม ratio (สีที่มากที่สุดใหญ่สุด) มี % ใต้หยดแต่ละอัน ถ้าการ์ดสูงเกินพื้นที่ stage ให้ย่อหลุมผสมสีในการ์ดลง (ใช้ 80%)
- **"สีของวันนี้เปลี่ยนไปนิดหนึ่ง":** หยดสีตกลงหลุมผสมสี มีวงคลื่นกระจาย
- **สีก่อนและหลังบันทึก:** รอยพู่กันสองอันวางเทียบกัน แต่ละอันมีชื่อสีกำกับ
- **ปุ่ม:** ปุ่มหลัก "ดูสมุดทั้งเล่ม" ไปหน้า `book` และปุ่มรอง "ระบายต่ออีกแผ่น" ไปหน้า `pick`

**จังหวะจริงที่ทำ (ขั้นที่ 9)** ภาพปกติ ~1.55 วินาที ถ้าขึ้นแผ่นใหม่ ~2.0 วินาที (ค่าอยู่ที่ `MOTION.save` ใน `lib/tokens.js`, ตารางเวลาใน `lib/saveTimeline.js`)
- โพลารอยด์ **รออยู่กลางโต๊ะ** ระหว่างกระดานเลื่อนซ้าย (ไม่ติดไปกับกระดาน) แล้วลอยลงช่อง
- ภาพใหม่จบที่เงาปกติ (เงาลึกมีแค่ช่วงลอยลงช่อง) พร้อมป้าย "ใหม่"
- ระหว่างลำดับ ปุ่มบันทึก ปุ่มเปลี่ยนหน้า และลูกศรแผ่นกดไม่ได้ ถ้าผู้ใช้กด back กลางทางลำดับจะหยุดและสถานะลงตัวที่ปลายทาง
- `prefers-reduced-motion`: ไม่มีภาพบิน ทุกส่วน fade พร้อมกันไม่เกิน 150ms (§3.6)

**รายละเอียดอื่น**
- ภาพใหม่มีป้าย "ใหม่" สี `--cover` ที่มุมขวาล่าง
- ถ้าบันทึกแล้วทำให้แผ่นปัจจุบันเกิน 4 ภาพ ให้แสดงแผ่นแทรกใหม่งอกออกมาก่อน (ดู §5.6) แล้วค่อยวางภาพ

### 5.5 `book`: สมุดและจานสีประจำวัน (`5-book`)

- **แถบกระดานซ้าย:** กว้าง 92px เห็นขอบกระดาษ มีข้อความแนวตั้ง "กลับไประบาย" ทั้งแถบเป็นปุ่มเดียว
- **หน้าคู่:**
  - ขนาด 1012×640 ที่ตำแหน่ง (176, 112)
  - ขอบรอบหน้าคือปก `--cover` กว้าง 14px
  - กลางเล่มมีเงาสันสมุด (inset shadow)
  - ด้านขวามีสายรัดพร้อมกระดุม
- **แท็บคั่นหน้า:**
  - อยู่ขอบบนของหน้าขวา ใช้วันที่เป็นป้าย เช่น "29 ก.ย."
  - สีแท็บคือสีเด่นของวันนั้น (§7.3)
  - แท็บของวันที่กำลังเปิดสูงกว่าอันอื่น 12px และใส่ `aria-current="page"`
  - สีตัวหนังสือบนแท็บต้องคำนวณให้ contrast ไม่ต่ำกว่า 4.5:1 (ขาวหรือ `--ink`)
- **หน้าซ้าย (ภาพของวัน):**
  - หัวหน้าเป็นชื่อวันที่ และจำนวนภาพ
  - ภาพโพลารอยด์กว้าง 196px ช่องภาพกว้าง 178px สัดส่วนเดียวกับกระดาษวาด 1112:612 (สูง ~98px) ภาพจริงจึงไม่ถูกตัดขอบ เอียงคนละมุม (-3° ถึง 3°) มีเทปแปะ
  - **แถบสี:** ใต้ตัวภาพ เหนือคำบรรยาย มีแถบสูง 8px มุมโค้งเล็กน้อย (3px) แบ่งช่องกว้างตาม `ratio` ของ `colors` (เรียงมาก→น้อย) โพลารอยด์เพิ่ม padding ด้านล่างเป็น 46px และแถบมี `aria-label` บอกชื่อสีกับ % ทุกสี เช่น "สีในภาพ: ฟ้า 55%, เทา 25%" (ปัดเป็นจำนวนเต็มที่รวมกันได้ 100 ด้วย largest remainder)
  - **เปิดดูภาพเดี่ยว:** กดที่ภาพไปหน้า `photo` (§5.8) ปุ่มโปร่งใสทับโพลารอยด์ มี `aria-label` "ดูภาพ {คำบรรยาย} ขยาย"
  - คำบรรยายใต้ภาพเป็นลายมือ "{HH:mm} · {อารมณ์}"
  - ถ้าภาพถูกปรับโทนไปทางบวก ให้ต่อท้ายคำบรรยายด้วย " → อุ่นขึ้น"
  - ตำแหน่งภาพใช้ชุด slot คงที่ 4 ตำแหน่งต่อแผ่น (ดูตัวเลขใน `5-book` และ `6-book-extra-leaf`) แล้วสุ่มมุมเอียงจาก `entry.id` เพื่อให้ผลออกมาเหมือนเดิมทุกครั้ง
- **หน้าขวา:** จานสีประจำวัน (ดู §5.7)
- **ด้านล่างหน้าขวา:** ลิงก์ "‹ {วันก่อนหน้า}" และข้อความ "หน้าล่าสุด" หรือลิงก์ "{วันถัดไป} ›"

### 5.6 แผ่นแทรกเมื่อหน้าซ้ายเต็ม (`6-book-extra-leaf`)

- **การแบ่งแผ่น:** หน้าซ้ายวางภาพได้ 4 ภาพต่อแผ่น ภาพของวันจึงถูกแบ่งเป็น `leaves = chunk(entriesOfDay, 4)`
- **แผ่นที่ 1:** คือตัวหน้ากระดาษเอง
- **แผ่นที่ 2 ขึ้นไป:** เป็นกระดาษแทรก (`#FDFCF9`) ขนาด 470×548 ติดเทปที่ขอบบน
  - พลิกขึ้นด้านบนด้วย `transform-origin: top` และ `rotateX()`
  - ไม่พลิกไปทางขวา เพื่อไม่ให้บังจานสี
- **เมื่อเปิดดูแผ่นก่อนหน้า:** แผ่นแทรกม้วนค้างอยู่ด้านบน แสดงเป็นแถบสูง 30px มีเงา
- **ขอบล่างของหน้าซ้าย:** แสดงขอบกระดาษซ้อนกันตามจำนวนแผ่น
- **ตัวบอกแผ่น:** "‹ แผ่น {n} / {total} ›" ลูกศรที่ไปต่อไม่ได้ให้ opacity 0.3 และ `disabled`
- **บนแผ่นล่าสุด:**
  - ถ้ายังมีที่ว่าง ให้แสดงช่องเส้นประพร้อมข้อความ "ภาพถัดไปของวันนี้จะมาอยู่ตรงนี้"
  - เทปของแผ่นที่เพิ่งงอกในวันนั้นมีป้าย "แผ่นใหม่" จนกว่าผู้ใช้จะพลิกดูแผ่นอื่น
- **เปิดสมุดครั้งแรก:** เปิดไปที่แผ่นล่าสุดเสมอ

### 5.7 จานสีประจำวัน (`DailyPalette`)

**หัวหน้า:** "จานสีของวันนี้" กับข้อความ "{n} ภาพ · {k} อารมณ์" หรือ "จานสีของ {วันที่}" ถ้าไม่ใช่วันนี้

**หลุมผสมสี (`MixingWell`)**
- เป็นจานกระเบื้องกลมขนาด 200px
  - ขอบนอก `#F1EEE8` เส้น `#DCD6CC`
  - หลุมใน `#FFFFFF` รัศมี 78
  - มีเงาด้านล่าง และแสงสะท้อนรูปวงรีสีขาว opacity 0.55
- ข้างในหลุม (clip เป็นวงกลม) วางหยดสีที่ดูดได้จากทุกภาพในวันนั้น ใช้ filter `wcm` รวมสีที่ใกล้กันเป็นก้อนเดียว ขนาดหยดตามน้ำหนักรวม `ratio × w` ของสีนั้น (สีปลายทางของภาพที่ปรับโทนอยู่ใน `colors` แล้ว จึงไม่ต้องเพิ่มหยดแยก)

**ชื่อสีของวัน**
- แสดงชื่อจาก `nameOfDay()` ฟอนต์ Mali 26px แบ่งเป็น 2 บรรทัด
- ตามด้วยรอยพู่กันของสีผสม และรหัส hex

**เส้นเวลา (`DayTimeline`)**
- เป็น SVG ขนาด 412×118 เส้นฐานโค้งเล็กน้อย
- แกนเวลา 00:00–24:00 ขีดบอกเวลาที่ 00:00, 06:00, 12:00, 18:00 และ 24:00 เว้นขอบซ้ายขวา 18px (แกนอยู่ที่ x = 18 ถึง 394) ให้หยดสีและป้ายเวลาไม่ถูกตัด
- แต่ละภาพเป็นหยดสีรูปหยดน้ำตั้งขึ้นจากเส้นฐาน ใช้สีที่เด่นที่สุดของภาพนั้น (`colors[0]`) ที่ตำแหน่ง `x = 18 + clamp(ชั่วโมงทศนิยม / 24, 0, 1) × 376` (ดู §8.3)
- ถ้าหยดสองอันใกล้กันเกินไป (ห่างน้อยกว่า 14px) ให้เลื่อนออกจากกันเล็กน้อยไม่ให้ทับกันสนิท โดยยังคงลำดับเวลาและอยู่ในกรอบแกน
- ภาพที่ถูกปรับโทนใช้หยดไล่สีแนวตั้ง จากสีเด่นไปสีที่ซึมเข้ามา (สีปลายทางที่มีใน `colors`)
- ถ้ามีไม่เกิน 3 ภาพ แสดงชื่ออารมณ์เหนือหยด ถ้ามากกว่านั้นให้ซ่อนชื่อ แล้วแสดงสรุปจำนวนในบรรทัดด้านล่างแทน
- ในหน้า `saved` ให้หยดของภาพใหม่มีวงเส้นประรอบ และป้าย "+1"

**สรุปท้ายหน้า:** ข้อความสั้นหนึ่งบรรทัด สร้างจาก template ไม่ใช้ AI
- "ส่วนใหญ่{อารมณ์หลัก} มีช่วง{อารมณ์รอง}ตอน{ช่วงเวลา}" (อารมณ์นับจากช่อง `emotion` ของแต่ละภาพ ไม่ใช่จากสี)
- ถ้ามี 5 ภาพขึ้นไป ใช้ "...วันนี้แวะมาบ่อยเลยนะ"

### 5.8 `photo`: ดูภาพเดี่ยวและชาร์ตสี

เปิดเมื่อกดภาพในสมุด (`book`) ภาพลอยขึ้นมาขยายกลางโต๊ะ ทับด้วยชั้นสี `--desk` ทึบประมาณ 85% ทั้ง stage (`desk/85`) เพื่อไม่ให้อ่านตัวหนังสือในสมุดด้านหลังได้ สมุดและแถบซ้ายยังอยู่ที่เดิม ไม่ได้ลด opacity เอง และกดไม่ได้ระหว่างอยู่ใน view นี้

- **การจัดวาง:** ภาพกับการ์ดอยู่กึ่งกลางแนวตั้งทั้งคู่ วางคู่กันกลางจอ ภาพซ้ายการ์ดขวา ห่างกัน 56px (flex `items-center justify-center gap-14`)
- **ภาพ:** โพลารอยด์ตัวเดิมขยายประมาณ 2.2 เท่า (กล่องประมาณ 431×425) เอียงเล็กน้อย (-2°) มีแถบสีใต้ภาพเหมือนใน §5.5 ตอนเปิดภาพลอยขึ้นด้วยการเลื่อนขึ้นและขยาย 0.6 → 1 ใน 600ms
- **การ์ดชาร์ตสี** (สไตล์บัตรตัวอย่างสี) กว้าง 460px ทุกอย่างอยู่ในการ์ดเดียว เรียงจากบนลงล่าง:
  - **หัวการ์ด:** ซ้ายคือหัวข้อ "สีในภาพนี้" และใต้หัวข้อมีบรรทัด "{เวลา} · {อารมณ์} · {ความเข้ม}" (ต่อท้ายอารมณ์ด้วย " → อุ่นขึ้น" ถ้าปรับโทน) ขวาบนคือปุ่ม "ปิด" (ไอคอน ✕)
  - **รายการสี:** แต่ละสีเป็นแถวหนึ่งแถว: รอยพู่กันหนา (stroke 20px, filter `wct`) ความยาวตาม `ratio` (สีที่มากที่สุดยาวเต็ม) ตามด้วยรหัส hex (ฟอนต์ mono) และ % ตัวหนา แสดงทุกสีที่เก็บไว้ (ไม่เกิน 5)
  - **ท้ายการ์ด:** แถบสัดส่วนรวมสูง 16px ของ `colors` ทั้งหมด
  - ไม่มีแถบเครื่องมือแยกที่ขอบล่างของจออีกแล้ว
- **การปิด:** ปุ่ม "ปิด", คีย์ Esc หรือคลิกพื้นที่ว่างนอกภาพและการ์ด กลับไป `book` ที่วันและแผ่นเดิม และคืนโฟกัสให้ปุ่มที่เปิดภาพ
- **การเข้าถึง:** กล่องเป็น `role="dialog"` `aria-modal="true"` เมื่อเปิดให้โฟกัสไปที่ปุ่มปิด และมี focus trap: Tab / Shift+Tab วนอยู่ในการ์ด (ถ้าโฟกัสหลุดนอกการ์ดให้ดึงกลับ)
- **hash:** `#photo` ข้อมูลภาพที่เปิดอยู่เก็บใน store (`photoEntryId`)

**เมื่อต่อข้อมูลจริง (ขั้นที่ 7):** หน้า `photo` ต้องโหลดภาพเต็มจาก `image_path` (WebP 1600px, §6.6) ไม่ใช่ `thumb_path` เพราะภาพถูกขยาย 2.2 เท่า ใช้ thumb เป็นภาพชั่วคราวระหว่างรอโหลดได้ ส่วนในสมุดยังใช้ thumb เหมือนเดิม

**แอนิเมชัน (ทำแล้วในขั้นที่ 9):** ภาพบินจากตำแหน่งจริงของมันในสมุดมาที่กลางโต๊ะ (FLIP ด้วย transform เท่านั้น 600ms) และบินกลับช่องเดิมตอนปิด ระหว่างบินช่องในสมุดซ่อนอยู่และกดปิดซ้ำไม่ได้ ถ้าไม่รู้ตำแหน่งต้นทาง (เช่นเข้าด้วยปุ่ม forward ของเบราว์เซอร์) ใช้การลอยขึ้นและขยายจากกลางโต๊ะแบบเดิม ภาพเต็มสลับเข้าหลังบินจบ

## 6. ผ้าใบสีน้ำ (`FluidCanvas`)

### 6.1 ฐานโค้ด
- ใช้ไลบรารี npm `webgl-fluid-enhanced` v0.8 (พัฒนาต่อจาก WebGL-Fluid-Simulation) ผ่าน `components/paint/FluidCanvas.vue` ยัง **ไม่ได้ port เป็นโมดูลเอง** (ถ้าทำ คือทางเลือกขั้น 5b ที่ `src/lib/fluid/`)
- API ที่ไลบรารีเปิดให้ใช้จริง: `start()`, `stop()`, `setConfig(partial)`, `multipleSplats(n)`, `splatAtLocation(x, y, dx, dy, color?)` (ไม่มี `init`, `pause/resume`, `clear` หรือ `exportImage`) FluidCanvas จึงทำเอง: รับ pointer เอง, ล้างผ้าใบด้วยการตั้ง dissipation สูงมาก ~8 เฟรม, หยุด/เริ่ม loop ด้วย `stop()`/`start()`, และจับภาพด้วย `capture()` แล้วส่งออกด้วย `lib/exportImage.js` (§6.6)
- ปิด bloom, sunrays และ shading แบบเรืองแสงทั้งหมด

### 6.2 ให้ดูเป็นสีน้ำบนกระดาษ ไม่ใช่แสงเรืองบนพื้นดำ
- **วิธีเก็บสี:** dye texture ให้เก็บ "ความเข้มของพิกเมนต์" ไม่ใช่สีแสง
- **display shader:** ผสมแบบลบสี (subtractive)

```glsl
vec3 pigment = dye.rgb;                    // สีพิกเมนต์ (0..1)
float density = clamp(length(dye.rgb) * K, 0.0, 1.0);
vec3 col = mix(paper, paper * pigment, 1.0 - exp(-density * ABSORB));
```

- **เนื้อกระดาษ:** คูณด้วย texture ผิวกระดาษสีน้ำ (noise หรือภาพสแกนที่วางซ้ำ) ให้สีไปเกาะตามร่องกระดาษ
- **ขอบเข้ม (edge darkening):** เพิ่มความเข้มตรงที่ gradient ของ density สูง จะได้ขอบเข้มเหมือนสีน้ำแห้ง
- **พื้น:** ใช้ `BACK_COLOR` เป็น `--paper`

### 6.3 พารามิเตอร์ตามอารมณ์

ตอนเข้าหน้า `paint` ให้หยดสีเริ่มต้นอัตโนมัติ (ค่าตั้งต้น ปรับจูนได้):

| อารมณ์ | จำนวนหยดเริ่มต้น | ความเร็วหยด | CURL | VELOCITY_DISSIPATION | ซึม (สัดส่วน / ขนาดวง) | ลักษณะ |
|---|---|---|---|---|---|---|
| happy | 5 | ×0.5 | 9 | 1.1 | 0.3 / ×5.5 | กระจายออกรอบทิศ สดใส |
| calm | 3 | ×0.3 | 3 | 0.7 | 0.3 / ×6 | ไหลช้า ซึมกว้างนุ่ม |
| excited | 3 | ×0.6 | 8 | 1.2 | 0.3 / ×5 | หมุนวน เข้มชัด |
| warm | 3 | ×0.45 | 6 | 0.7 | 0.3 / ×6 | นุ่ม กว้าง |
| sad | 3 | ×0.3 | 4 | 0.8 | 0.3 / ×5.5 | ไหลลงล่างช้า ๆ (มีแรงถ่วงลง 4 วินาทีแรก) |
| angry | 3 | ×0.6 | 7 | 1.2 | 0.3 / ×5 | พุ่งเป็นช่วง ใช้สีขอบเข้มมากขึ้น |
| anxious | 6 (หยดเล็ก) | ×0.4 | 5 | 1.1 | 0.3 / ×5 | กระจายเป็นจุดเล็ก ๆ ทั่วกระดาษ |
| tired | 2 | ×0.1 | 2 | 0.9 | 0.3 / ×5.5 | แทบไม่เคลื่อนที่ ซึมช้า |

**สีไม่จาง (สีน้ำที่แห้งติดกระดาษ):** `DENSITY_DISSIPATION` เป็น **0 พอดี** ทุกอารมณ์ ห้ามตั้งเป็นค่าเล็ก ๆ: บัฟเฟอร์สีของไลบรารีเป็นเลข 16 บิต ค่าตั้งแต่ ~0.0001 ขึ้นไปทำให้ทุกเฟรมถูกปัดลงอย่างน้อย 1 หน่วยเล็กสุด สีหายเหลือ ~9% ภายใน 60 วินาที (วัดแล้ว) ส่วน 0 เหลือ ~97% ความต่างของแต่ละอารมณ์จึงอยู่ที่ CURL, ความเร็วหยด, ขนาดหยด กับ `VELOCITY_DISSIPATION` ซึ่งตั้งให้การไหลและการซึมจบภายใน ~3–5 วินาทีถ้าไม่แตะ (velDiss มากหยุดเร็ว) แตะหรือปาดอีกครั้งก็ไหลต่อได้ ค่า curl สูงทำให้น้ำวนต่อไปไม่หยุด จึงลดลงมากเมื่อเทียบกับเดิม เป้าที่วัดด้วย `scripts/measure-fluid.mjs` (หยด 1 หยดกลางผ้าใบ ทุกอารมณ์): ความเข้มรอบจุดที่ 5 วินาที ≥ 60% ของที่ 1 วินาที, พื้นที่สี 5→15 วินาทีเพิ่มไม่เกิน 10%, ความเข้มที่ 60 วินาที ≥ 95% ของที่ 5 วินาที

**ซึมออกแบบสีน้ำ (bleed):** การดันน้ำอย่างเดียวขยับก้อนสีไปทั้งก้อน ไม่ทำให้พื้นที่สีโต (วัดแล้วพื้นที่ที่เห็นสีแทบไม่เปลี่ยนต่อให้ curl/ความเร็วสูงมาก) หยดจึงลงเป็นสองส่วน: หยดแรกลงสัดส่วน (1 − `bleed`) ส่วนที่เหลือค่อย ๆ ซึมออกที่จุดเดิมเป็นวงที่กว้างขึ้นเรื่อย ๆ จนวงสุดท้ายกว้าง `reach` เท่าของรัศมีหยดแรก ตลอด `bleedMs` = 3500 ms แล้วหยุด (12 ขั้น) ใช้กับหยดแรกและการแตะ ไม่ใช้กับกดค้างเบา ๆ (strength < 0.5) เป้าที่วัด: พื้นที่สีที่ 5 วินาที ≥ 1.6 เท่าของที่ 1 วินาที (ได้ ~1.7–1.9), พื้นที่ 5→15 วินาทีเพิ่มไม่เกิน 10% (ได้ ~0–1%), ความเข้มรอบจุดที่ 5 วินาที ≈ 83–89% ของรอบก่อนหน้า, ที่ 60 วินาที ≥ 95% ของที่ 5 วินาที

**กันสีสะสมจนดำ:** เมื่อสีไม่จาง การหยดซ้ำที่เดิมจะบวกกันไม่หยุด ผ้าใบจึงจำปริมาณสีที่ลงในแต่ละช่อง 80px (รีเซ็ตเมื่อล้าง) หน่วยคือค่าสีสูงสุดของช่องสีหนึ่งในบัฟเฟอร์ (1 = ดำสนิท) และ **จำกัดตอน splat จริง** ไม่ให้เกิน `INK_CAP` = 0.85 (หยดที่ที่ว่างไม่พอถูกลดแรงลงให้พอดีเพดาน) ช่องที่เต็มแล้วดันน้ำเบาลง (ขั้นต่ำ 10%) และหยดเบาตอนกดค้างดันน้ำตามแรงของมัน ใช้กับหยดทุกแบบ (เริ่มต้น, แตะ, กดค้าง, สีปลายทาง) ทดสอบกดค้าง/แตะรัวจุดเดิม 2 นาที: ไม่ดำ (พิกเซลมืดสุดไม่ต่ำกว่า ~20% ของความสว่าง) และสีไม่กระจายทั่วผ้าใบ

**สาดสีตอนเข้าหน้า paint:** หยดเริ่มต้นไม่ลงพร้อมกัน แต่ทยอยลงภายใน `splashMs` = 1000 ms ตาม pattern ของอารมณ์ (burst: พุ่งออกเร็ว ๆ ช่วงต้น · drift/still: ไล่เรียงสม่ำเสมอ · fall: ทยอยจากบนลงล่าง · pulse: จังหวะเท่ากัน · scatter: ผุดสุ่ม) แต่ละหยดซึมต่อตามหัวข้อ "ซึมออกแบบสีน้ำ" ระหว่างสาด (ราว 1 วินาที) ห้ามกดบันทึก (`app.splashing`) ลดการเคลื่อนไหว: ทุกหยดลงทันทีโดยไม่ซึมเป็นจังหวะ ผ้าใบ fade เข้า 150 ms

**ระดับอารมณ์ → การสาด** (`SPLASH_LEVELS` ใน `emotions.js` แยกจาก `INTENSITY_FACTOR` ที่ยังคุมความเข้มสีต่อหยด [0.6, 1, 1.5] และจากน้ำหนักจานสีของวัน §8.1):

| ระดับ | intensity | คูณจำนวนหยด | คูณขนาดหยด | คูณระยะกระจาย |
|---|---|---|---|---|
| นิดหน่อย | 0 | ×1.3 | ×1.2 | ×1.15 |
| พอประมาณ | 1 | ×2.2 | ×1.3 | ×1.25 |
| มากเลย | 2 | ×3.2 | ×1.4 | ×1.35 |

(คูณกับจำนวนหยดเริ่มต้นของอารมณ์; ระยะกระจาย ×1 = ช่วงตำแหน่ง 15–85% ของกระดาษ) พื้นที่สีหลังสาด (วัดที่ 8 วินาที) เป็น ~2 เท่าของแบบเดิมทุกระดับ เช่น สงบ 12→26%, 26→55%, 37→75% ของผ้าใบ

**สีของแต่ละหยด:** สุ่มจากสีอารมณ์ 3 ระดับ (§3.2) โดยให้น้ำหนักสีเนื้อ 60% ขอบเข้ม 20% และสีจาง 20%

### 6.4 สีอุ่นสำหรับอารมณ์ลบ (ผู้ใช้เลือกเอง)
- ใช้กับ `sad`, `angry`, `anxious` และ `tired` เท่านั้น (อารมณ์ล่าสุดของแผ่นเป็นตัวตัดสิน)
- **ทำไมให้ผู้ใช้เลือกเอง:** เดิมระบบหยดสีปลายทางเข้ามาเองหลังผู้ใช้แตะผ้าใบ 8 วินาที แต่การที่แอปเปลี่ยนสีที่ผู้ใช้วาดโดยไม่ถามเท่ากับตัดสินแทนว่าอารมณ์ของเขาควรเปลี่ยน อารมณ์ลบไม่ใช่สิ่งที่ต้องแก้ ผู้ใช้อาจอยากอยู่กับมันต่อ จึงเปลี่ยนเป็นเครื่องมือที่ผู้ใช้หยิบเอง และโน้ตที่ชวนแบบไม่ผูกมัด (ปฏิเสธได้และไม่ถามซ้ำ) แอปไม่แตะผ้าใบเองเลยจนกว่าผู้ใช้จะสั่ง
- **เครื่องมือ "สีอุ่น" (ใน `ToolTray` §5.3):**
  - แตะ = หยดสีปลายทางตรงจุดนั้น ขนาดและความเข้มใกล้เคียงหยดของเครื่องมือ "เติมหยด": รัศมี `WARM_SIZE` 0.5 (เติมหยดของ sad = 0.18 × 3 = 0.54) และความเข้มคูณ `WARM_STRENGTH` 1 บนฐานเดียวกับเติมหยด (ตามความเข้มของอารมณ์เดิมด้วย) ค่าตั้งต้นอยู่ใน `src/lib/devState.js` (ผู้พัฒนาจูนจากแผง `?debug` แล้วเลือก 0.5 / 1 / 4)
  - กดค้างเกิน 400ms = หยดเบา ๆ ต่อเนื่องที่จุดนั้นด้วยสีเดียวกัน เหมือนเติมหยด (ทุก 120ms ด้วยแรง 0.1 ผ่านตัวกันสีสะสม)
  - **สี:** ไล่ตามลำดับใน `SHIFT_TARGETS` (§3.2) ของอารมณ์ล่าสุด หนึ่งการแตะ/กดค้างหนึ่งรอบ/"ลองดู"หนึ่งครั้ง ได้หนึ่งสี แล้ววนกลับสีแรกเมื่อครบ นับต่อแผ่น รีเซ็ตเมื่อเริ่มแผ่นใหม่
  - ตัวกันสีสะสม (`takeInk`, `INK_CELL`/`INK_CAP`) ใช้กับหยดสีอุ่นด้วย เป็นตัวเดียวที่จำกัดสีอุ่น **ไม่มีเพดานพื้นที่ 50% แล้ว** เพราะผู้ใช้เป็นคนหยดเอง
  - reduced motion: กดค้างหยดช้าลงครึ่งหนึ่ง (ห่างขึ้น 2 เท่า)
- **โน้ตชวน (ครั้งเดียวต่อแผ่น):** แสดงเมื่ออารมณ์ล่าสุดเป็นอารมณ์ลบ และครบทั้งสองข้อพร้อมกัน ข้อความและปุ่มดู §5.3
  - **ครบ 10 วินาที:** นับเวลาจริงตั้งแต่ `pointerdown` ครั้งแรกบนผ้าใบของแผ่นนั้น ไม่ต้องกดค้างหรือระบายต่อเนื่อง (เดิมนับเฉพาะเวลาที่กดค้าง ผู้ใช้ที่ลากสั้น ๆ จึงสะสมไม่ถึงเกณฑ์)
  - **พักมือ 1.5 วินาที:** ไม่มี `pointerdown` และไม่มี pointer ที่กดค้างอยู่มา 1.5 วินาที `pointermove` ที่ไม่ได้กด (hover) ไม่ถูกนับเป็นการแตะ ไม่รีเซ็ตตัวนับ เมาส์ที่ปล่อยปุ่มแล้วแต่ไม่ได้รับ `pointerup` (ปล่อยนอกหน้าต่าง) ถือว่าปล่อยแล้วเมื่อ `pointermove` ถัดไปมี `buttons = 0` ไม่ให้ค้างเป็น "กดอยู่"
  - **หยุดนับเมื่อออกจากหน้า paint** (และตอนกำลังล้างผ้าใบ) แล้วนับต่อเมื่อกลับมา เริ่มใหม่/แผ่นใหม่/บันทึก = รีเซ็ต
  - **โหมด dev:** `?shiftSpeed=10` เร่งทั้งสองเวลา (ไม่เร่ง simulation) และ `?debug` แสดงกล่องเล็กมุมซ้ายล่างของจอ บอก "นับตั้งแต่แตะครั้งแรก", "พักมือ" และสถานะโน้ต (รอ/แสดง/ปิดแล้ว) พร้อมแถบเลื่อน "เวลาก่อนโน้ตขึ้น" 3–30 วินาที และ "เวลาพักมือ" 0.5–5 วินาที (ค่าตั้งต้น 10 / 1.5 อยู่ใน `src/lib/devState.js` มีผลกับแผ่นปัจจุบันทันที) และปุ่ม "รีเซ็ตโน้ต" เริ่มนับของแผ่นนี้ใหม่โดยไม่ล้างภาพ ทั้งสองอย่างทำงานเฉพาะ `import.meta.env.DEV`
- **ตอนบันทึก:**
  - ตั้ง `shifted = true` เฉพาะเมื่อผู้ใช้หยดสีอุ่นเองอย่างน้อย 1 หยด (รวมหยดที่ "ลองดู" ทำให้) คำบรรยาย "→ อุ่นขึ้น" ใช้กติกาเดิม
  - ไม่ต้องใส่สีปลายทางลง `colors` เอง เพราะสีเหล่านั้นอยู่บนผ้าใบและถูกดูดมาพร้อมภาพ (§6.6)
- **ข้อห้าม:** ไม่มีข้อความที่ตัดสินอารมณ์ เช่น "ทำให้รู้สึกดีขึ้น" ทุกถ้อยคำต้องเป็นการชวนที่ปฏิเสธได้
- **"ลองดู":** หยดตัวอย่าง `WARM_DEFAULTS.samples` = 4 หยด ห่างกัน 280ms วางห่างเท่า ๆ กันตามเส้นรอบกระดาษ (ห่างขอบ 40px เริ่มจากตำแหน่งสุ่ม) พุ่งเข้าด้านในช้า ๆ (`SHIFT_SPEED` 200) สีไล่ตามลำดับ `SHIFT_TARGETS` ต่อจากสีที่ใช้ไปแล้วในแผ่น ขนาดและความเข้มเท่าหยดที่แตะ
- **ค่าที่เก็บไว้จากระบบอัตโนมัติเดิม:** `SHIFT_TARGETS`, ตัวกันสีสะสม และ `SHIFT_SPEED`
- **แผงปรับค่า (dev เท่านั้น):** เปิดด้วย `?debug` (`src/dev/DebugPanel.vue` โหลดแบบ lazy ภายใต้ `import.meta.env.DEV` จึงไม่ติดไปใน production build ตรวจแล้วว่าไม่มีข้อความของแผงใน `dist/`) พับเก็บได้
  - ตัวนับของโน้ตชวน (นับตั้งแต่แตะครั้งแรก, พักมือ, สถานะ รอ/แสดง/ปิดแล้ว)
  - เลือกอารมณ์ (ตั้ง `selection.emotion` ด้วย) แล้วมีแถบเลื่อนของ `INITIAL_SPLATS` (1–12) และทุกค่าตัวเลขใน `FLUID_PARAMS`: ความเร็วหยด (0–3), curl (0–60), velDiss (0–2), ขนาดหยด (0.02–0.6), ความเข้ม brightness (0.5–4) พร้อมตัวเลขข้างแถบ ผลเห็นบนผ้าใบทันที (แก้ object ใน `emotions.js` ตรง ๆ ในหน่วยความจำ และตั้ง curl/velDiss ให้ไลบรารีใหม่)
  - ปุ่ม "หยดสีเริ่มต้นใหม่" (ล้างผ้าใบแล้วหยดสีเริ่มต้น ทางเดียวกับ "เริ่มใหม่") และ "คัดลอกค่า" (JSON ของอารมณ์นั้น ไปแก้ `emotions.js` เอง เพราะค่าที่ปรับไม่ถูกเก็บ)
  - แถบเลื่อนสีอุ่น: ขนาดหยด (0.1–3), ความเข้ม (0.5–5), จำนวนหยดลองดู (1–10)
- **การตรวจ (ขั้น 6 แก้ไข):** วัดบน headless Chrome ด้วย `?shiftSpeed=10`
  - หยดเริ่มต้นของ `excited` (ปล่อยไว้ ไม่แตะ) ครอบพื้นที่ 21–31% ของกระดาษ (วัดพิกเซลที่ต่างจากสีกระดาษ 4 รอบ ทั้งปกติและ reduced motion) ไม่เกินเพดานประมาณ 45%
  - โน้ต (จำลองด้วย puppeteer, `?shiftSpeed=10&debug`): ขยับเมาส์ hover ค้างบนผ้าใบโดยไม่กด 6 วินาทีหลังแตะหนึ่งครั้ง โน้ตขึ้น (hover ไม่รีเซ็ตพักมือ), ลากสั้น ๆ หลายครั้งด้วยเมาส์และ touch โน้ตขึ้น, กดค้าง 4 วินาที โน้ตไม่ขึ้นจนกว่าจะปล่อย, ออกไปหน้าสมุดแล้วกลับ ตัวนับหยุดแล้วนับต่อ
  - กด Tab ถึงปุ่ม "ลองดู" และ "ไว้ก่อน" ได้ทั้งสองปุ่ม
  - `prefers-reduced-motion: reduce`: เครื่องมือ โน้ต และการบันทึก `shifted` ทำงานเหมือนปกติ (โน้ตเหลือ fade 150ms)

### 6.5 เครื่องมือและการโต้ตอบ
- **ปาดสี (ค่าเริ่มต้น):** ลาก pointer แล้วใส่ velocity โดยไม่เพิ่มสี ใช้ `splat` ที่ color เป็นศูนย์ ให้ความรู้สึกเหมือนกวนสีที่มีอยู่
- **เติมหยด:** แตะแล้วหยดสีอารมณ์ลงที่จุดนั้น ถ้ากดค้างเกิน 400ms ไม่ว่าอยู่ในเครื่องมือไหน ให้หยดสีต่อเนื่อง
- **Pointer events:**
  - ใช้ Pointer Events รองรับ multi-touch บน iPad
  - ตั้ง `touch-action: none` บน canvas
  - ห้ามให้หน้าเลื่อนหรือซูมระหว่างที่ระบาย
- **ประสิทธิภาพ:** `SIM_RESOLUTION` 128, `DYE_RESOLUTION` 1024 บนเดสก์ท็อป และ 512 บน iPad (ตรวจจาก `navigator.maxTouchPoints > 1`)

### 6.6 การบันทึกภาพและดูดสี
- **ภาพเต็ม:** render 1 เฟรมแล้วอ่าน pixel จาก framebuffer ส่งออกเป็น WebP คุณภาพ 0.85 ขนาด 1600 px ด้านยาว
- **ภาพย่อ:** สร้างภาพย่อ 480px สำหรับแสดงในสมุด
- **ดูดสีจากภาพ (`src/lib/extractColors.js`)** เพื่อให้จานสีมาจากสีที่ผู้ใช้ผสมเองจริง
  1. ย่อภาพให้ด้านยาวประมาณ 200px (วางบนพื้น `#FBFAF6`)
  2. `getPaletteSync(img, { colorCount: 8, quality: 1, ignoreWhite: false })` จาก `colorthief` v3
  3. ตัดสีที่ใกล้สีกระดาษ `#FBFAF6` ออก (ระยะ RGB น้อยกว่าประมาณ 28 ปรับจูนได้) แต่เก็บสีจางของน้ำซึมไว้
  4. นับ pixel ของภาพย่อ: ข้าม pixel ที่เป็นกระดาษ ที่เหลือจัดเข้าสีในจานที่ใกล้ที่สุด แล้วคิด `ratio = จำนวน pixel ของสี / จำนวน pixel ที่ไม่ใช่กระดาษ`
  5. เก็บสูงสุด 5 สี เรียงจากมากไปน้อย เป็น `colors = [{ hex, ratio }]` โดย `ratio` รวมกันได้ 1 (ถ้าไม่มี pixel ที่ไม่ใช่กระดาษเลย ให้ใช้สีอารมณ์ ratio 1)
- อัปโหลดขึ้น Storage ทั้งสองไฟล์ แล้วจึง insert แถวใน `entries`
- **ช่วงก่อนขั้นที่ 7 (ยังไม่มี Supabase):** ภาพเต็ม ภาพย่อ และ entries ที่ผู้ใช้บันทึกเก็บใน IndexedDB ของเบราว์เซอร์ (database `colorscrap`, store `entries`, keyPath `id`, เก็บ Blob ในแถวเดียวกับข้อมูล) โหลดกลับตอนเปิดแอป รีเฟรชแล้วยังอยู่ (`src/lib/imageStore.js`) entry จาก mock ไม่เก็บและไม่มีภาพ จึงแสดงหยดสีจำลอง ในโหมดจริง (ขั้นที่ 7) ภาพไป **Supabase Storage** (`image_path`, `thumb_path` ตาม §7.2) และ entries ไปตาราง `entries` IndexedDB เหลือหน้าที่เดียวคือคิวอัปโหลดซ้ำด้านล่าง (record มี `user_id` ของเจ้าของ ผู้ใช้อื่นบนเครื่องเดียวกันไม่เห็น) ส่วน record เก่าที่ไม่มี `user_id` จะถามผู้ใช้ก่อนย้ายเข้าบัญชีเสมอ
- **การแสดงภาพจริง:** โพลารอยด์ในสมุดและหน้า `saved` ใช้ภาพย่อ หน้า `photo` (§5.8) ใช้ภาพเต็ม ใส่ในกรอบเดิมด้วย `object-fit: cover` ถ้า entry ไม่มีภาพให้แสดงหยดสีจำลองเหมือนเดิม object URL สร้างตอนแสดงและ `revokeObjectURL` เมื่อถอด component หรือเปลี่ยนภาพ
- **ถ้าอัปโหลดไม่สำเร็จ:** เก็บ Blob ไว้ใน IndexedDB แล้วลองใหม่อัตโนมัติ (5 → 15 → 60 วินาที → ทุก 5 นาที และเมื่อเน็ตกลับมา) พร้อมแสดง toast "ยังบันทึกไม่ได้ จะลองใหม่ให้อีกครั้ง"

  - ช่องอีเมลและรหัสผ่านแบบเส้นประ
  - ปุ่มหลัก "เข้าสมุด" / "สร้างสมุดใหม่" และข้อความ error ภาษาไทย

- `VITE_USE_MOCK` ไม่ตั้งหรือเป็นค่าอื่นนอกจาก `false` = โหมดจำลอง (ไม่ต่อ Supabase ไม่มีหน้า login)

### 7.2 Schema

```sql
create table public.profiles (
  id uuid primary key references auth.users on delete cascade,
  display_name text not null check (char_length(display_name) between 1 and 20),
  avatar text not null default 'cat'
    check (avatar in ('cat','plant','cloud','moon','flower','fish','mug','star')),
  cover_color text not null default '#9E2F2A',
  likes text[] not null default '{}',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table public.entries (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null default auth.uid() references auth.users on delete cascade,
  created_at timestamptz not null default now(),
  local_date date not null,            -- วันที่ตามเวลาเครื่องผู้ใช้ ใช้จัดกลุ่มรายวัน
  local_time time not null,            -- เวลาตามเครื่องผู้ใช้ ใช้วางบนเส้นเวลา
  emotion text not null                -- อารมณ์ล่าสุดของแผ่น (= emotions[ล่าสุด])
    check (emotion in ('happy','calm','excited','warm','sad','angry','anxious','tired')),
  emotions text[] not null             -- อารมณ์ที่หยดลงแผ่นนี้ตามลำดับ (อย่างน้อย 1 ค่า) คำบรรยายใช้ "แรก → ล่าสุด"
    check (cardinality(emotions) >= 1
      and emotions <@ array['happy','calm','excited','warm','sad','angry','anxious','tired']
      and emotions[cardinality(emotions)] = emotion),
  intensity smallint not null check (intensity between 0 and 2),
  colors jsonb not null,               -- [{"hex":"#5FA3C8","ratio":0.42}, ...] สีที่ดูดจากภาพ (ratio รวม 1)
  shifted boolean not null default false,
  image_path text not null,            -- {user_id}/{id}.{ext} ใน bucket paintings (ext ตามชนิดไฟล์จริง: webp, jpg, png)
  thumb_path text not null             -- {user_id}/{id}_thumb.{ext}
);
create index entries_user_date on public.entries (user_id, local_date, local_time);

alter table public.profiles enable row level security;
alter table public.entries  enable row level security;

create policy "own profile" on public.profiles
  for all using (auth.uid() = id) with check (auth.uid() = id);
create policy "own entries" on public.entries
  for all using (auth.uid() = user_id) with check (auth.uid() = user_id);
```

**Storage**
- สร้าง bucket `paintings` แบบ **private**
- รับ `image/webp`, `image/jpeg`, `image/png` (Safari รุ่นเก่าถอยไป JPEG); path เก็บตามนามสกุลจริงใน `image_path`/`thumb_path` แอปอ่านภาพจาก path ในแถวเสมอ
- policy: อนุญาตเฉพาะ path ที่ `(storage.foldername(name))[1] = auth.uid()::text`
- ตอนแสดงภาพในแอป ใช้ `createSignedUrl` อายุ 1 ชั่วโมง และ cache ไว้ใน store

**หมายเหตุ:** `emotion` (อารมณ์ล่าสุด) ยังเก็บไว้ใช้กับคำบรรยายภาพ การ์ดอารมณ์ และบรรทัดสรุปประจำวัน ส่วนสีที่แสดงในสมุดทั้งหมดมาจาก `colors`

**เหตุผลที่เก็บ `local_date` และ `local_time` แยกไว้:** ถ้าใช้ `created_at` ซึ่งเป็น UTC มาจัดกลุ่ม ผู้ใช้ในไทยที่บันทึกตอนหลังเที่ยงคืนจะไปตกอยู่ผิดวัน

### 7.3 ข้อมูลที่คำนวณได้ (ไม่ต้องเก็บ)

| ค่า | วิธีคำนวณ |
|---|---|
| ภาพของวัน | `entries` ที่ `local_date` ตรงกัน เรียงตาม `local_time` |
| แผ่นในวันนั้น | `chunk(entriesOfDay, 4)` |
| สีเด่นของวัน | รวมน้ำหนัก `ratio × w` ของแต่ละสีทั้งวัน (`w = 0.75 + 0.25 × intensity`) โดยสีที่ใกล้กันมากรวมกลุ่มก่อน แล้วเลือกกลุ่มที่ **น้ำหนัก × saturation (HSV)** สูงสุด เพื่อไม่ให้สีจางของน้ำซึมที่กินพื้นที่มากชนะสีของหยดจริง ถ้าเท่ากันใช้สีของภาพล่าสุด สีหยดบนเส้นเวลาของแต่ละภาพเลือกด้วย `ratio × saturation` เช่นกัน ส่วนชาร์ตสีของภาพ (§5.8) และจานสี (§8) ยังใช้ `ratio` จริง |
| สีผสมของวัน | `mixColors()` (ดู §8) |
| ชื่อสีของวัน | `nameOfDay()` (ดู §8) |
| แถบ 7 วันและแท็บคั่นหน้า | ดึงสีเด่นของแต่ละวัน |

## 8. อัลกอริทึมจานสี (`src/lib/palette.js`)

### 8.1 `mixColors(entries)` (รับ `entries` ที่มี `intensity` และ `colors: [{ hex, ratio }]`)

ให้ผสมในระบบสี HSL ไม่ใช่เฉลี่ย RGB ตรง ๆ เพราะการเฉลี่ย RGB ทำให้สีที่อยู่ตรงข้ามกันบนวงล้อสีกลายเป็นสีเทาหม่น

**น้ำหนักของแต่ละสี**
- น้ำหนักต่อภาพ: `w = 0.75 + 0.25 × intensity`
- ทุกสีใน `colors` ของภาพนั้นมีน้ำหนัก `ratio × w`
- ไม่มีน้ำหนักพิเศษให้สีปลายทางของภาพที่ปรับโทน เพราะสีเหล่านั้นอยู่ใน `colors` อยู่แล้ว (ถ้านับเพิ่มจะซ้ำ)

**ขั้นตอนคำนวณ**
1. **hue:** ค่าเฉลี่ยแบบวงกลม (circular mean ของเวกเตอร์ cos และ sin) ถ่วงน้ำหนักด้วย `ratio × w` นับเฉพาะสีที่ saturation > 0.15 สีเทาอย่าง `tired` จะไม่ไปดึง hue
2. **saturation และ lightness:** ค่าเฉลี่ยถ่วงน้ำหนักจากทุกสี
3. แปลงผลกลับเป็น hex

**ตัวอย่างตรวจผล** (intensity 1 ทุกภาพ, `colors` ของแต่ละภาพเป็นสีอารมณ์เดียว `ratio = 1`)

| ภาพในวันนั้น | ผลที่ได้ |
|---|---|
| calm + tired | `#5788A3` (h 201, s 0.30, l 0.49) |
| calm + tired + calm | `#5892B1` (h 201, s 0.36, l 0.52) |

ค่า hex ที่เห็นใน mockup เป็นตัวอย่างประกอบเท่านั้น ให้ยึดผลจากสูตรนี้

### 8.2 `nameOfDay(mixHex, lastLocalTime)`
ชื่อสีประกอบจาก **"{กลุ่มสี}{ตัวขยาย}{ช่วงเวลา}"**

**1. กลุ่มสี** จาก hue ใน HSL

| hue | ชื่อ |
|---|---|
| 345–15 | แดง |
| 15–40 | ส้ม |
| 40–65 | เหลือง |
| 65–170 | เขียว |
| 170–215 | ฟ้า |
| 215–250 | น้ำเงิน |
| 250–290 | ม่วง |
| 290–345 | ชมพู |

ถ้า saturation < 0.15 ใช้ "เทา"

**2. ตัวขยาย** (ใช้ข้อแรกที่ตรง)

| เงื่อนไข | คำ |
|---|---|
| มีกลุ่มสีรองที่อยู่คนละกลุ่มกับสีหลัก และกลุ่มนั้นไม่ใช่ "เทา" | "อม{กลุ่มสีรอง}" |
| saturation 0.15–0.33 | "หม่น" |
| saturation 0.33–0.45 หรือ lightness < 0.5 | "ครึ้ม" |
| lightness > 0.72 | "อ่อน" |
| saturation > 0.6 | "สด" |
| ไม่ตรงข้อไหนเลย | ไม่ใส่ |

**วิธีหากลุ่มสีรอง:** แปลงสีใน `colors` ของทุกภาพเป็นกลุ่มสีตามตารางด้านบน แล้วรวมน้ำหนัก `ratio × w` ต่อกลุ่ม ไม่นับกลุ่มเดียวกับสีหลัก และไม่นับ "เทา" จากนั้นเลือกกลุ่มที่น้ำหนักรวมมากที่สุด ถ้าเท่ากันใช้กลุ่มของภาพล่าสุด

**3. ช่วงเวลา** จากเวลาของภาพล่าสุด

| เวลา | คำ |
|---|---|
| 05–11 | ยามเช้า |
| 11–14 | เที่ยงวัน |
| 14–17 | ยามบ่าย |
| 17–19 | ยามเย็น |
| 19–24 | ยามค่ำ |
| 00–05 | กลางดึก |

**ตัวอย่างที่ต้องได้ตามดีไซน์** (ใช้เป็น unit test; fixture รูปแบบ `{ time, intensity, colors: [{ hex, ratio }] }` โดย `calm = #5FA3C8`, `tired = #5B6773`, `happy = #F1BE48`, `excited = #E2688A` และทุกภาพมีสีเดียว `ratio = 1` ยกเว้นระบุไว้)

| ภาพในวันนั้น | ผลที่ต้องได้ |
|---|---|
| 09:12 calm, 13:40 tired | "ฟ้าหม่นเที่ยงวัน" (s ≈ 0.30) |
| เพิ่ม 15:12 calm | "ฟ้าครึ้มยามบ่าย" (s ≈ 0.36) |
| calm 3 ภาพ (รวมภาพล่าสุด 18:45), happy 11:05, tired 14:00 (ไม่ปรับโทน), excited 16:30 | "ฟ้าอมชมพูยามเย็น" (h ≈ 213 กลุ่มรองเสมอกันระหว่างเหลืองกับชมพู ชมพูชนะเพราะเป็นภาพล่าสุดของกลุ่มที่เสมอกัน) |
| เหมือนข้างบน แต่ tired เป็นภาพที่ปรับโทน `colors = [{ #5B6773, 0.7 }, { #F7DE99, 0.3 }]` | "ฟ้าอมเหลืองยามเย็น" (h ≈ 209 เหลืองได้น้ำหนัก 1.3 มากกว่าชมพู 1.0) |
| `mixColors` ภาพเดียวที่มีหลายสี `[{ #5FA3C8, 0.6 }, { #F1BE48, 0.4 }]` | `#55D9C1` (h ≈ 169, s 0.64, l 0.59) ใช้ตรวจว่า hue ถ่วงด้วย `ratio` |

ตอนแสดงผล ให้ตัดชื่อเป็น 2 บรรทัด คือส่วนกลุ่มสีกับตัวขยาย และส่วนช่วงเวลา

### 8.3 `timelineX(localTime)`
- คำนวณ `18 + clamp((h + m/60) / 24, 0, 1) × 376` (แกนเวลา 00:00–24:00 เว้นขอบซ้ายขวา 18px)
- `spreadXs(xs, minGap = 14)` รับ x ที่เรียงจากน้อยไปมาก ดันตัวที่ใกล้กันเกินไปไปทางขวาให้ห่างอย่างน้อย `minGap` แล้วถ้าล้นขอบขวา (x > 394) ให้เลื่อนกลับทางซ้ายทีละตัว คืนค่าตามลำดับเดิม (ใช้เป็น unit test)

## 10. คุณภาพ

- **การเข้าถึง:**
  - ทุกปุ่มเป็น `<button>` หรือ `<a>` จริง
  - ปุ่มที่มีแต่ไอคอนต้องใส่ `aria-label`
  - ชุดปุ่มเลือกใช้ `role="group"` คู่กับ `aria-pressed`
  - focus ต้องมองเห็นชัด เช่น `outline: 3px dashed var(--e-calm); outline-offset: 4px`
- **Contrast:** ข้อความต้องไม่ต่ำกว่า 4.5:1 สีตัวหนังสือบนแท็บสีอารมณ์ต้องคำนวณเลือกให้อัตโนมัติ
- **ข้อความใน UI:**
  - ภาษาไทยทั้งหมด และไม่มีข้อความ error สีแดง
  - ตัวอย่างข้อความ error: "ยังบันทึกไม่ได้ เน็ตอาจหลุดอยู่ จะลองใหม่ให้อีกครั้ง"
- **ความเป็นส่วนตัว:**
  - ไม่เก็บ analytics ที่ผูกกับอารมณ์
  - ในตั้งค่ามีปุ่ม "ลบข้อมูลทั้งหมด" ซึ่งลบแถวใน DB และไฟล์ใน Storage
- **การทดสอบ:**
  - unit test ด้วย Vitest สำหรับ `mixColors`, `nameOfDay`, `timelineX`, `chunk` และขั้นนับสัดส่วนสีใน `extractColors` (ใช้ภาพสังเคราะห์ที่รู้สัดส่วนล่วงหน้า)
  - ทดสอบด้วยมือบน Safari iPad, Chrome และ Safari บน Mac

## 12. ลำดับการพัฒนาที่แนะนำ

1. **โครงโปรเจกต์:** Vite + Vue + Pinia, tokens, ฟอนต์, `Stage` (scaling), `SvgDefs`, ผิวกระดาษ
2. **UI kit:** `HandButton`, `Tape`, `Polaroid`, `EmotionBlob`, `Doodle`, `WatercolorBlob`
3. **ทุกหน้าจอด้วยข้อมูลจำลอง:** สร้างทุก view ตาม §5 ด้วยข้อมูล mock ใน store และใส่การเปลี่ยนสถานะของวัตถุบนโต๊ะ
4. **ส่วนที่กดได้:** `hello` กับ `pick` ให้ทำงานครบ
5. **ผ้าใบ:** port fluid มาทำ shader สีน้ำ ใส่พารามิเตอร์ตามอารมณ์ เครื่องมือ การ export ภาพ และดูดสี (`extractColors.js`, §6.6)
6. **สีอุ่นสำหรับอารมณ์ลบ (ผู้ใช้เลือกเอง):** ตาม §6.4
7. **Supabase:** auth, profiles, entries, storage, RLS และเชื่อมกับ store (ย้ายภาพและ entries จาก IndexedDB ชั่วคราวของขั้นที่ 5 ไป Supabase Storage / ตาราง `entries`)
8. **สมุด:** จัดกลุ่มรายวัน แท็บคั่นหน้า แผ่นแทรก `DailyPalette` และ `palette.js` พร้อม unit test (Vitest)
9. **แอนิเมชันตอนบันทึก:** ทำลำดับในหน้า `saved` (§5.4)
10. **เก็บงาน:** reduced motion, ทดสอบ performance บน iPad, การเข้าถึง และกรณีเน็ตหลุด
