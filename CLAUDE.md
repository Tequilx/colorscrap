# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm install` — install deps (Node `^22.18.0 || >=24.12.0`)
- `npm run dev` — Vite dev server with HMR (includes vue-devtools plugin). UI kit gallery (dev only) at `/?kit`
- `npm run build` / `npm run preview` — production build / serve it
- `npm test` — Vitest (`vitest run`): `src/lib/*.test.js` (`palette`, `extractColors`, `uuid`, `flip`, `saveTimeline`, `dyeLimit`, `sound`, `daylight`, `cursors`), `src/lib/share/*.test.js` (`maskName`, `formatThaiDate`/file names, `shareOrDownload`) and `src/dev/fluidMetrics.test.js`. Pure-function tests only, no component tests; `@` alias works via vite.config.js

No linter is configured.

## Architecture

ColorScrap is a Vue 3 + Vite + Tailwind 3 (PostCSS) app, a university AI final project: a watercolour mood sketchbook. **`docs/SPEC.md` is the source of truth** (read it before building a screen); reference mockups are in `docs/design/screens/` and `docs/design/style-board.html`. Plain JavaScript only (no TypeScript), `<script setup>`. UI text is in Thai, and so are code comments — keep that convention. `@` aliases `src/` (vite.config.js, jsconfig.json).

- **Single "desk", no router.** The whole app is one fixed 1280×800 stage (`components/desk/Stage.vue`) scaled to fit the window. The current screen is `view` in the Pinia store `stores/app.js` (`hello | cover | pick | paint | saved | book | photo`); transitions go through `go()` which enforces the table in SPEC §4.1. Persistent objects (`Scrapbook`, `DrawingBoard`, `EmotionPalette`) are never unmounted — they move/fade by `view`. Sync `view` with `location.hash` for the back button; do not add Vue Router.
- **Design tokens live in `src/lib/tokens.js` only** (plain data, no Vue imports). `tailwind.config.js` imports it, so use utilities (`bg-desk`, `text-ink-soft`, `bg-e-calm`, `font-hand`, `rounded-hand`, `ease-desk`) and never hard-code hex in components. Only runtime-changeable values (`--cover`, `--cover-spine`, `--cover-strap`) are CSS variables in `styles/tokens.css`. Cover spine/strap use plain RGB `mixRgb` (`lib/color.js`); `mixColors` (SPEC §8.1, HSL) is only for the daily palette.
- `components/ui/` is the kit (`HandButton`, `Tape`, `Polaroid`, `EmotionBlob`, `Doodle`, `WatercolorBlob`, `ColorStrip`). SVG paths for faces, avatars, icons and blobs are in `lib/emotions.js` / `lib/doodles.js`.
- **Sound (`lib/sound.js`)**: all synthesised with Web Audio, no files. Context is created after the first pointerdown/touchend/keydown (`attachSound` in `App.vue`); `soundOn` (localStorage `colorscrap.sound`, default on) off = nothing scheduled and master gain 0. Max 6 voices (`createVoicePool`), master → compressor → soft clip (peak ≤ −1 dBFS). `?debug` exposes `window.__soundPeak`/`__soundVoices`. Callers: `FluidCanvas` (drop/brush/bloom), `stores/app.js` (open book, leaf flip, `paperRise`/`tape` on the save timeline), `App.vue` (button taps). New sounds go in `sound.js` only.
- **Desk light (`components/desk/DeskLight.vue`, `lib/daylight.js`)**: time-of-day overlay (day 06–17 / dusk 17–19 / night 19–06; `?time=day|dusk|night` forces it, also in production) rendered as the first child of `Stage.vue`'s desk div, i.e. *under* the whole stage, so it never touches the canvas, book photos or cards (measured: canvas pixels and `extractColors` identical in all three). Layers cross-fade by opacity only (2 s); colours are `LIGHT` in `lib/tokens.js`; dust motes pause outside night and are still with reduced motion.
- **Pick brush (`components/pick/PickBrush.vue`)**: SVG brush over the emotion grid (`pointer-events: none`), rAF tween lift → dip → rest that always restarts from the current pose (rapid picks follow immediately). Card geometry constants must match `EmotionPalette.vue`. Set its transform from JS only (a `:style` binding gets re-applied on every re-render and snaps it back). Reduced motion: static at `HOME`, only the tip colour changes.
- **Cursors (`lib/cursors.js`)**: hand-drawn SVG cursors, only when `pointer: fine` (`--cursor-finger` set on `<html>` by `installCursors`, rule in `assets/app.css` skips elements with `data-cursor`). The FluidCanvas input layer sets its own cursor per tool (smear = finger with emotion-coloured tip, drop = brush in emotion colour, warm = brush in warm colour). Keep cursor SVGs valid XML (no duplicate attributes — an invalid image silently falls back to `auto`). Touch devices are unchanged.
- **Saved well (`components/saved/SavedWell.vue`)**: the mixing well on `SavedCard` as a standalone component (props `entry`, `before`, `day`; `play()` exposed). Plays once after mount: drop falls → 3 ripples + `sound.drop` → well colours cross-fade from the day's previous colours to the new ones (1.2 s). Transform/opacity only; reduced motion = static ripples + colour fade only.
- `src/KitGallery.vue` renders every kit component; it is lazy-loaded by `App.vue` only when `import.meta.env.DEV` and the URL has `?kit`.
- **Animation (step 9).** Durations/easing are `MOTION` in `lib/tokens.js` (tailwind `duration-450/600` multiply `--motion-scale`; dev `?motion=slow` sets it to 3 and `ms()` in `lib/motion.js` follows). Animate `transform`/`opacity`/`clip-path` only (iPad); `DrawingBoard` is a fixed 1280×800 layer moved by transform + clip-path, never left/top/width/height. `reducedMotion` (`lib/motion.js`, reactive) is for JS and for placements that move objects off-screen — hidden state must then stay in place and only fade; `app.css` also limits transitions to opacity/colour. Don't animate `box-shadow` (cross-fade layers instead).
  - **Save sequence:** `app.saveToBook()` captures first, then `runSaveSequence` drives `savePhase` (`idle → shrink → book → leaf? → drop → tape → card → idle`) with timers from `saveSchedule()`; `SavedFlight.vue` plays the polaroid with WAAPI on the same schedule (the captured canvas is reused as the shrinking image). While `savePhase !== 'idle'`, `go()`, `setLeaf`, `clearCanvas` and the save button are blocked; the upload queue waits (`sequenceActive`). Anything long-running must register `app.onCancel(fn)` — `setView()` (browser back) and `resetSession()` call `cancelSequences()` which must leave the final state consistent. `busy` = save phase / leaf flip / photo flight.
  - **Photo FLIP:** `PhotoSlot` sends its centre in stage coords (`lib/flip.js`, found via `[data-stage]`), `PhotoView` flies the polaroid with WAAPI and hides the real slot with `photoHiddenId` until it lands; thumb first, full image after the flight.
  - **Leaf flip:** `PhotoPage` keys each leaf layer by `leafIndex` inside a `<Transition>` (`leaf-fwd`/`leaf-back`); changing day skips the animation. Daily palette stagger replays only on `app.bookTick` (entering book, not from photo).

## Gotchas

- SVG filters (`wob`, `wc`, `wcm`, `wct`, `wcs`, `grain`) are defined once in `SvgDefs.vue` and used as `filter-wob` etc. Never put `wob` on large areas, things that animate constantly, or long text (put it on a frame element, as `HandButton` does) — iPad Safari performance.
- Keep the fluid instance in a plain `let`, never `ref()`/`reactive()`: Vue proxies interfere with WebGL. `paint/FluidCanvas.vue` wraps `webgl-fluid-enhanced` v0.8 (kept for step 5a; patching its display shader with patch-package or porting PavelDoGreat's simulation is the optional 5b, decided after seeing 5a). Its public API is `start/stop/setConfig/multipleSplats/splatAtLocation` only, so FluidCanvas works around it:
  - Pointers: the library's own mouse/touch handling is bypassed (touch uses `pageX`, wrong under the scaled Stage). A transparent overlay div takes Pointer Events and calls `splatAtLocation` (smear = hex `"#000000"`; drop = no hex). `splatAtLocation` x is device px (×dpr), y is CSS px.
  - Never pass a real hex to `splatAtLocation`/`colorPalette` expecting exact colour: the library uses only its hue/saturation, takes V from `brightness`, and multiplies by 1.5. `lib/dye.js` converts a target colour into `{ palette hex, brightness }`; `colorful` must stay `true` or `colorPalette` is ignored.
  - Subtractive look: canvas is opaque with `inverted: true` (CSS `invert(1)`) and `backgroundColor = invertedHex(paper)`, so dye = 1 − colour. Anything reading the canvas (`capture()`) must undo the invert (done with `difference` against white). Per-emotion `brightness` in `FLUID_PARAMS` (`lib/emotions.js`) is the dye strength tuned so colours match `EMOTION_COLORS`; measure with extractColors, don't guess.
  - Clear = set dissipation ~1000 for 8 frames (no public clear, and recreating the instance leaks FBOs). **`DENSITY_DISSIPATION` must be exactly 0**: the library's dye buffer is half float and any value ≥ ~1e-4 gets truncated by at least one ULP per frame, so paint vanishes in ~1 min (measured ~9% left vs ~97%). Paint never fades; it dries instead (below). Per-emotion look = `FLUID_PARAMS` (brightness/speed/curl/velDiss/radius/pattern are main's originals; `splash` is the only tuned per-emotion value). `bleed` (ring fill, looked like airbrush) and `drift` (water-pushed arms) were removed entirely — don't reintroduce.
  - **Drying (`FluidCanvas` `dryFrame`/`applyDry`, `FLUID_GLOBAL.flowTime`/`dryTime`/`dryDamp`):** after the last input the water flows normally (the emotion's `velDiss`/`curl`) for `flowTime` (2.5 s), then `velocityDissipation` ramps ease-in-out to `dryDamp` and `curl` to 0 until `dryTime` (10 s), so the water settles by itself; density is never touched. Time is *simulated* seconds (`simNow` accumulates `min(dt, 1/60)` per frame while the canvas runs and is not asleep), not the wall clock: on wall clock a slow device dried before the water had spread (measured area dropped by up to 40%). `lastInputAt` is set by `wake()` (tap, drag, hold, warm drops, every splash drop; gravity of `sad` is `auto` and does not count) and by `dryFrame` while a pointer is held. New input snaps back to normal at once. Curl must ramp down too: vorticity confinement re-injects energy and kept high-curl emotions moving at speed 2–12 for minutes (measured). Once peak speed < `STILL_SPEED` the existing sleep path pauses the simulation.
  - **Black guard lives on the GPU (`lib/dyeLimit.js`, `FluidCanvas` `dyeSplat`/`splatGpu`):** colour is added by our own splat program (vertex shader borrowed from the library's splat program, `buildProgram`) that reads the pixel's existing dye and adds only what keeps (a) max channel ≤ `gpuCap` 0.85 and (b) displayed lightness ≥ `minLight` 0.3, softly above `knee` 0.8 (same function as the JS reference in `dyeLimit.js`, unit-tested). The old CPU guard (ink map blocking drops, `takeInk`/`warmCap`/`blackGuard` switch) is removed: it over-estimated and blocked drops while real dye was far below the cap (measured: 16/20 taps blocked after 30 s of painting); the ink map remains only as an estimate (`depositInk`, `lowerInk`, finding "ลองดู" spots), and if the guard shader cannot be built `splatGpu` simply returns false (no colour). A single drop is scaled so its peak ≤ cap before the shader (same look as before); water push always accompanies colour. Performance: velocity-only pushes (smear, gravity) call the library's splat program directly (`pushWater`), smears are coalesced per frame, `getBoundingClientRect` is cached per frame, `pressureIterations` is 12 and dye is 768 (512 on touch). The step is skipped (`togglePause`, render keeps running so `capture()` still works) only when the peak water speed — read back asynchronously every 0.5 s with a PBO + fence — is below `STILL_SPEED`. Splash multipliers (`splash` per emotion) were re-tuned for this guard (overlapping drops are no longer blocked).
  - Entering `paint` splashes the initial drops over `FLUID_GLOBAL.splashMs` (1 s) in the emotion's pattern. Drop count/size/spread = `SPLASH_LEVELS` × the emotion's `splash` triple (a continuous area multiplier: the integer drop count is rounded and the remainder goes into drop size), separate from `INTENSITY_FACTOR` which still scales ink per drop; targets are ~2× main's settled area per emotion × level (SPEC §6.3); `app.splashing` (set by `FluidCanvas` `splash` event) blocks saving until the drops have landed; with reduced motion everything lands at once with a 150 ms fade. Tuning/verification: `scripts/measure-fluid.mjs` (scenarios `drop|tap|hold|initial|three`, `--diff 15:60`, `--replace`, `MODULE=FluidCanvas.vue` to patch another module) and `scripts/measure-fps.mjs` for GPU-synced frame times (needs Playwright outside the repo; see headers); `?debug` shows the texture type/format the library actually uses.
  - Capture must run inside `requestAnimationFrame` (no `preserveDrawingBuffer`).
- Negative-mood warm colour (SPEC §6.4) is user-chosen, never automatic. ToolTray shows a 4th tool "สีอุ่น" (`app.warmAvailable`: latest sheet emotion is negative); `FluidCanvas` drops `SHIFT_TARGETS` colours on tap/hold (per-sheet `sheet` state, reset in `clear()`) and emits `shifted` → `app.sheetShifted` → `entry.shifted` on the first warm drop. The one-time invite note (`WarmNote.vue`, state `app.warmNote`: idle/open/done) fires via `invite` once `warmTune.noteDelay` (10s) has passed since the sheet's first pointerdown and no pointerdown/held pointer for `warmTune.noteIdle` (1.5s) (hover is ignored; timer pauses outside `paint`). Warm drops use `warmTune` (`lib/devState.js`), "ลองดู" drops several samples around the paper edge. Dev only: `?shiftSpeed=10` speeds up both timings, `?debug` opens `src/dev/DebugPanel.vue` (lazy, DEV-only): live sliders for `FLUID_PARAMS`/`INITIAL_SPLATS`/`FLUID_GLOBAL` (incl. dry time / flow time)/warm values/note delays, redrop, "รีเซ็ตโน้ต" (restart the current sheet's note timer without clearing), copy JSON.
- Colours of a saved painting are extracted with the **npm** `colorthief` v3 (`getPaletteSync`, returns Color objects with `.hex()`), not the old v2 CDN `window.ColorThief` — that script tag is gone. Entries store `colors: [{ hex, ratio }]` (SPEC §6.6, §7.2).
- `lib/palette.js` follows SPEC §8 and the SPEC §8.1/§8.2 worked examples are unit tests (`palette.test.js`); if the formula stops matching an example, stop and ask rather than editing the example. `nameOfDay(mixHex, lastLocalTime, entries)` needs `entries` for the secondary hue group ("อม…"); without it there is no modifier. `mixColors` uses raw `colors` (no near-colour merging), while `colorWeightsOfDay` (merged) feeds `dominantColorOfDay` and `MixingWell`. `SavedCard` shows "สีของวันนี้ยังคงเดิม" instead of the arrow when the before/after names are equal.
- **Warm drops (SPEC §6.4) are a bloom, not a stamp, one colour per emotion (`WARM_TONES`, `warmShade`; icon uses the same colour; `SHIFT_TARGETS` is gone):** `bloomAt` in `FluidCanvas.vue` runs per drop (tap, hold ≥ 700 ms apart, every "ลองดู" sample; on for emotions in `WARM_BLOOM`): ring push + one `liftDye` (own multiply shader; dye × (1 − lift·g) in the middle, × (1 + rim·ring) capped at `INK_CAP` on the rim) at t = 0, then **one continuous curve computed from real elapsed time** (`bloomFrame`, rAF, same result at 30 and 60 fps; the old four chunks + sustain drops made a visible second pulse): deposit rate rises (sin) to its peak at 250 ms then falls linearly to 0 at `bloomMs` (3 s; `BLOOM_TAIL`), radius grows monotonically 0.55 → 1.05, lifts are applied per elapsed time (level 1.2× → 0.6× of `lift` over 1 s, then to 0) because old paint flows back into the middle while the canvas is wet (measured), water push only in the first 500 ms with a slowly rotating direction (`BLOOM_PUSH`, `BLOOM_TURNS`; per-emotion `WARM_PUSH_GAIN` in `emotions.js`; a longer or one-directional push gave a second hump / a comet tail). Emissions are throttled to ≥ 30 ms (wider when many blooms overlap); deposits below `BLOOM_MIN_SHARE` accumulate instead of being dropped (a larger value gave visible steps at ~2.3–2.8 s). Hold uses the same curve shortened to 900 ms with no ring push, no first lift and no filler drops. Reduced motion: one lift + one deposit, no push. Measured against 3d31f84: area and centre R−B at 3 s within about ±10% on blank paper (painted canvas varies ±15% run to run even before the change), one motion peak at ~0.3–0.7 s (angry/anxious keep a plateau because of their curl). Never let `Infinity`/`NaN` reach the water push: a NaN velocity splat blanks the whole canvas. Do not add local velocity damping (creates divergence, made it worse) and keep `push` modest (stronger push floods the middle faster). Tune via `?debug` (`warmTune.bloom/lift/liftRadius/rim/push/bloomMs/bloomPeak/strength`). Scripts need `waitUntil: 'domcontentloaded'` + aborting font requests when offline.
- `HandButton` has its own `relative`, so don't put `absolute`/`fixed` on it directly — wrap it in a positioned div.
- Open book (`book/OpenBook.vue`) is rendered by `Scrapbook.vue` for both `book` (1:1) and `saved` (scale 1.15, left page zoom); the closed cover layer is separate. `DrawingBoard.vue` stays mounted: full screen in `paint`, a 92px strip in `book`, hidden otherwise.
- Saving: `app.saveToBook()` is async (captures the canvas via the painter registered by `DrawingBoard`, runs `lib/extractColors.js`, encodes WebP via `lib/exportImage.js`); entries carry `image`/`thumb` Blobs (markRaw) until uploaded. Images are shown through `lib/useEntryImage.js`: Blob object URL while local, else the signed URL of `image_path`/`thumb_path` (cache + auto-renew in `stores/imageUrls.js`). Mock entries have neither and keep the fake blob drawing. "เริ่มใหม่" needs a second tap within 3s (SPEC §5.3), there is no undo/toast.
- **Saving images out (SPEC §5.9, `src/lib/share/`):** PhotoView ("เก็บรูปไว้": card with colour chart / image only) and DailyPalette ("เก็บรูป": card of the open day) build PNGs entirely on the client, nothing is uploaded. Canvas 2D only (`cardDraw.js` helpers, `cards.js` `renderPhotoCard`/`renderDayCard`, `exporter.js` loads the entry image: local Blob, else `signPaths` → `fetch` → `createImageBitmap` so the canvas is never tainted); no html-to-image/foreignObject (Safari). SVG filters can't run in canvas, so the hand-drawn look is imitated (value-noise edges, dashed rules, tape, cached grain). Fonts must be loaded with Thai sample text (`loadCardFonts`) because Google Fonts splits by unicode-range, and text is placed by line-box metrics (`LINE` in `cardDraw.js`: Mali 1.30em, IBM Plex Thai 1.65em). The card layout was verified against `docs/design/screens/7a|7b` by rendering both (`scripts/render-cards.mjs` writes samples to the git-ignored `scripts/out/`). `shareOrDownload` returns `shared|cancelled|downloaded|blocked`: `AbortError` is silent, `NotAllowedError` (gesture lost while the image was being made) keeps the file and `stores/share.js` shows a toast with a "แตะเพื่อบันทึก" button that shares again in a fresh gesture (`toast.show(text, ms, { label, run })`). User name on cards goes through `maskName` (grapheme-aware). The day card reuses `lib/mixingWell.js` and `palette.js` (`dayColor`, `timelineX`, `spreadXs`) so it matches the book page.
- Mock data (steps 3–4) must use the same entry shape as the Supabase schema in SPEC §7.2.

## Supabase (step 7)

- `VITE_USE_MOCK !== 'false'` = mock mode (no network, no login view, profile in localStorage, entries in IndexedDB). `.env` sets `true`, `.env.production` `false`; for real testing put `VITE_USE_MOCK=false` in `.env.local` (gitignored by `*.local`). Never print the key values. `VITE_SUPABASE_ANON_KEY` holds a publishable key (`sb_publishable_...`); `lib/supabase.js` exports `USE_MOCK`/`supabase`/`BUCKET`, `lib/remote.js` is the only place that talks to tables/Storage.
- `supabase/schema.sql` is run by the user in the SQL Editor (idempotent). Bucket `paintings` is private and accepts webp/jpeg/png; file extension follows `blob.type` and the real path is stored in `image_path`/`thumb_path`.
- Boot (`main.js`) awaits `auth.init()` + profile/entries load before mount. New view `login` (`components/auth/LoginCard.vue`); signing out (or session loss) is handled by a watcher in `App.vue` → `app.resetSession()`, `profile.reset()`, `entries.reset()`, view `login`. The desk is used by many people in turn, so anything per-user must be cleared there.
- Upload: `addEntry` adds the entry at once (uuid id), saves a record with `user_id` to IndexedDB, then `stores/uploadQueue.js` `flush()` uploads (full → thumb → insert, idempotent) and deletes the record; failures toast once and retry with backoff and on `online`. IndexedDB records without `user_id` are pre-step-7 images: `LegacyPrompt.vue` asks before adopting them (never silently).
